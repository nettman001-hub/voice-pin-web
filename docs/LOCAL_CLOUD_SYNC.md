# 라이브 화면 로컬 읽기와 안전한 클라우드 쓰기

2026-09-29 기준. 이 설계는 두 저장소의 원자적 동시 커밋이 아니라, 로컬에 먼저 기록한 작업을 서버 확인 후 완료하는 동기화 방식이다. 네트워크 장애 중에도 화면은 로컬 데이터로 계속 동작하며, 미전송 작업은 재시도한다.

## 판매

- 판매 레코드와 UPSERT/DELETE 작업 로그를 워크스페이스별 단일 상태로 저장한다. DELETE도 재시도 가능한 tombstone으로 보존한다.
- 여러 탭의 로컬 작업은 IndexedDB read/write 트랜잭션에서 항목별 변경분으로 병합한다. 한 탭의 전체 배열로 다른 탭의 미전송 판매를 덮어쓰지 않는다. 저장 완료 후 localStorage/BroadcastChannel 알림으로 다른 탭의 화면과 큐도 갱신한다.
- 같은 워크스페이스의 서버 쓰기는 순서대로 실행한다. 작업 토큰이 일치할 때만 ACK를 적용하며, 최신 수정 내용을 이전 요청의 값으로 덮어쓰지 않는다.
- 조회 시작 이후 수정·추가·삭제·서버 확정된 항목은 오래된 조회 결과보다 우선한다. 더 최신 조회의 결과가 먼저 도착하면 이전 조회는 폐기한다.
- 조회가 미전송 작업 도중 시작됐어도 이후 ACK를 변경으로 기록한다. 뒤늦게 도착한 조회가 이미 저장된 판매를 삭제하거나 되돌리지 않는다.
- 최초 판매 조회는 페이지를 모두 읽는다. PostgREST의 기본 행 수 제한으로 판매가 누락되면 로컬 통계도 틀리기 때문이다.
- 방송별 수량/금액과 구매자의 전체 누적 횟수/금액은 서로 다른 범위를 집계한다. 보류·취소 건은 제외한다.

## 댓글

- 수신 즉시 표시하고, 미전송 댓글은 워크스페이스·회차별 영속 outbox에 넣는다. 회차를 바꿔도 이전 회차 큐는 삭제하지 않는다.
- 정식 UUID 회차가 준비되기 전에는 전송하지 않는다. 임시 회차가 정식 회차로 바뀔 때만 대기 댓글을 승격한다.
- `ingest-comments`는 신규/중복 모두 서버의 정식 댓글 ID와 buyer ID를 응답한다. ACK된 댓글만 outbox에서 제거하고 로컬의 `stream-*` ID를 교체한다.
- ACK 전 선택한 댓글을 판매 확정할 때는 전송 확인 후 정식 ID로 다시 해석한다. 닉네임을 UUID 대신 보내지 않는다.
- 서버가 구 버전일 때만 쓰기 직후 댓글 목록을 한 번 읽어 ACK를 보완한다. 새 서버에서는 이 추가 조회가 없다.
- bootstrap/60초 피드 보정에서 로컬의 정식 댓글 ID를 서버에 전달한다. 서버는 동일 워크스페이스·회차에서 실제로 없어진 ID만 `deletedCommentIds`로 반환한다. 최신 50건에서 빠졌다는 이유로 과거 댓글을 삭제하지 않는다. 삭제 확인은 100개씩 나눠 조회하고 실패하면 삭제로 처리하지 않는다.
- 삭제된 댓글의 로컬 tombstone은 오래된 피드/ACK에 의한 재등장을 막는다. 삭제 알림은 댓글 화면의 기존 링버퍼와 대기 항목에도 반영한다. 이 원격 삭제 보정은 수정된 `sales-api`의 배포가 필요하다.

## 댓글/판매멘트 기록 (2026-09-30)

- `/comments`의 메뉴·제목은 `댓글/판매멘트 기록`이다. 댓글과 판매멘트 탭에서 동일한 회차·기간·검색 필터를 사용하고, 선택한 탭의 기록을 TXT/CSV로 내려받는다.
- 판매멘트는 판매 저장에 성공한 문장만이 아니라 상품 설명·수정·후속 발화 등 STT가 확정한 전체 로그다. 현재 방송의 메모리 전체 로그, 이 PC의 회차별 저장 로그, 기존 `workspace_settings` 클라우드 백업을 회차·기록 ID로 병합한다. 최근 300건 화면 제한을 다운로드에 적용하지 않는다.
- 판매멘트 탭을 열거나 회차를 바꾸거나 새로고침할 때만 클라우드 이력을 읽는다. 전체 회차 조회는 페이지를 모두 읽고, 모든 조회·로컬 키·늦게 도착한 응답을 워크스페이스별로 격리한다.
- 기존 로그의 `timestamp`는 한국어 시계 문자열이므로 생성 ID에 포함된 실제 시각으로 날짜를 복원한다. 새 로그에는 ISO `recognizedAt`도 저장한다. CSV는 UTF-8 BOM, 따옴표/줄바꿈 escaping, 수식 실행 방지 처리를 포함한다.
- 방송 중 전체 로그는 청취한 PC에서 즉시 조회된다. 다른 기기에서는 기존 방송 종료/회차 전환 시 클라우드에 저장된 로그를 조회한다. 저장되지 않은 과거 멘트와 원본 오디오 파일은 이 기능으로 복원할 수 없다. 클라우드 조회 실패 시 경고와 함께 이 PC의 기록만 제공한다. DB 스키마·Edge Function 변경은 없다.

## 저장공간과 계정 전환

- 핵심 상태는 localStorage와 IndexedDB에 복구 사본을 유지한다. localStorage 실패 시 메모리 읽기를 유지하고, 새로고침 시 더 최신 복구 사본을 선택한다.
- ACK된 댓글 원본과 삭제 tombstone도 영속 복구 및 저장 오류/재시도 대상이다. 서버 ACK로 outbox가 비워진 후에도 댓글 근거를 새로고침 시 복원한다.
- 양쪽 영속 저장이 모두 실패하면 경고를 표시한다. 이때 메모리만으로 새로고침·창 종료 후 복구를 보장할 수 없다. 댓글 근거를 삭제해서 판매 저장공간을 확보하지 않는다.
- 워크스페이스 키와 계정 세대 번호로 비동기 응답을 검사한다. 상품 이미지 URL 해석 뒤에도 재검사하며, 이전 계정의 응답이 현재 계정 캐시를 갱신하지 않는다.
- 활성 상품이 `null`이면 화면·활성 상품 캐시·bootstrap 캐시에서 모두 해제한다.

## 통신과 한계

- `/live`의 2초 화면 갱신에는 Supabase HTTP 조회가 없다. bootstrap, 실제 쓰기, 기존 Realtime 알림에 따른 판매 동기화, 60초 피드 보정은 유지한다. 따라서 전체 Supabase 통신이 0건이 되는 것은 아니다.
- IndexedDB도 브라우저 정책·디스크 여유에 따라 실패할 수 있다. 영속 저장 실패를 숨기지 않는 것이 안전장치이며 무조건적인 오프라인 무손실을 보장하지 않는다.
- 다른 탭의 저장소 변경을 피드에 반영하지만, 독립 탭/기기가 같은 판매를 동시에 수정하는 경우의 분산 충돌 해결은 별도 서버 revision/CAS 정책이 필요하다. 단일 탭의 쓰기 순서 보장을 분산 트랜잭션으로 해석하면 안 된다.
- 장시간 오프라인 댓글 큐는 데이터를 임의 절삭하지 않는다. 기기의 저장 용량을 초과하면 경고에 따라 연결과 저장공간을 복구해야 한다.
