# 판매자 로직분석01codex

관리자 메뉴 `/admin/seller-logic-analysis-01-codex`에서 기존 판매 AI 설정의 슬롯 1 또는 슬롯 2를 선택한다. 구매 의사, 주문번호 안내, 판매자 배정, 가격 협상, 닉네임 연결, 상품·옵션, 취소·정정은 모두 선택한 AI가 판단한다. 코드는 제공된 원문 ID와 댓글의 정확한 닉네임 등 응답 형식만 검증한다.

## 실시간 처리

- 댓글 도우미의 플랫폼 댓글과 Soniox 판매자 멘트를 수집하고 즉시 화면에 표시한다.
- 기본 5초 주기로 새 자료와 짧은 겹침·AI가 남긴 미완료 문맥을 1차 AI에 보낸다. 전체 방송 원문은 브라우저에 보관하며 반복 전송하지 않는다.
- 1차 AI는 거래 신호와 구매 의사 댓글 ID를 반환한다. 구매 의사는 2차 판매 연결이 끝나기 전에 Soniox 닉네임 갱신에 전달된다.
- 2차 AI는 신호 전후 최대 60초 범위에서 현재 도착한 근거를 읽는다. 근거가 충분하면 즉시 확정하고, 이후 관련 자료·발화 수정이 오면 같은 거래를 다시 연결한다. 뒤 60초가 도착할 때까지 무조건 기다리지 않는다.
- STT 안정 토큰은 최대 3초 단위로 내보낸다. 문장 종료와 토큰 확정은 구별하며, AI가 이어 읽기 문맥과 실제 원문을 함께 판단한다.

## Soniox 닉네임과 세션 교체

세션 시작에 최근 댓글 닉네임 최대 50개를 넣으며 Latin 닉네임의 한국어 발음도 함께 제공한다. AI가 새 구매 의사를 감지했을 때 첫 갱신은 즉시 시도하고, 다음 갱신들은 직전 구매 의사 갱신 시도부터 최소 5초 간격으로 묶는다. 현재 세션에 이미 포함된 닉네임은 불필요하게 교체하지 않는다. 이 메뉴는 일반 댓글 도착만으로 30초마다 세션을 교체하지 않는다.

교체 중 새 음성은 최대 60초의 PCM 저널에 보관한다. 새 세션이 유효한 응답을 보내야 전환하며, 실패하면 저널을 기존 세션에 전달한다. 기존 세션의 마지막 응답도 종료까지 수신한다. 연결 지연 한도 초과나 마지막 응답 시간 초과는 화면에 표시한다. 네트워크·제공자 실패 상황까지 음성 무손실을 보장하는 구조는 아니다.

## 판매 확정 목록과 전표

AI가 `CONFIRMED`로 반환한 거래의 댓글 닉네임, 상품·옵션, 수량, 합계 가격을 상단에 표시한다. 보류·검토·취소 및 원문 근거는 아래 판매 적재함에 계속 표시한다.

실시간 자료는 기본적으로 확정 즉시 댓글 도우미 프린터에 순차 출력한다. 기존 도우미 전표 양식(구매자, 합계 금액, 회차)을 사용한다. 프린터는 댓글 도우미에서 설정해야 한다. 불러온 예제 자료는 자동 출력하지 않고 거래별 수동 출력만 제공한다.

출력 ID는 전체 분석 세션과 AI 거래 ID를 SHA-256으로 만든다. 같은 누적 결과는 다시 출력하지 않으며, 응답 시간 초과 재시도는 같은 출력 버전을 사용한다. 상품·옵션·가격·수량 정정과 명시적 재출력은 버전을 올린다. 확정 취소는 아직 전송하지 않은 출력을 건너뛰고 이미 출력된 전표의 확인 안내를 표시한다. 자동 출력 해제는 아직 기기에 전송하지 않은 자동 작업을 취소한다.

분석과 출력 상태는 현재 페이지 세션에서 유지된다. 결과 JSON은 내려받을 수 있다. 이 실험 메뉴는 중앙 판매 장부에 자동 저장하거나 새로고침 후 출력 대기열을 복원하지 않는다.

## 검증

`npm test`, `npm run build`로 응답 계약, 1차 구매 의사 조기 전달, 분할 발화, 닉네임 갱신 간격·동시 도착·음성 보관, 출력 순서·중복 방지·정정·취소·재시도·자료 출처를 검증한다. 실제 슬롯 호출과 Soniox 합성 음성 검증 결과는 `artifacts`의 Codex 검증 JSON에 기록한다. 실제 방송 플랫폼과 물리 프린터의 종단 검증은 방송·프린터가 연결된 환경에서 수행한다.

2026-10-06 검증에서 운영 적용 v33의 슬롯 2(DEEPSEEK/deepseek-flash)는 대표 4개 사례를 통과했다. 슬롯 1(LM_STUDIO/gemma-4-e4b-it)은 자유형 요청·단순 설명 구분을 처리했으나 분할 배정 연결 실패와 JSON 출력 오류가 남았다. 오류 응답은 확정·출력에 적용하지 않는다. 현재 설정으로 방송을 테스트할 때는 슬롯 2를 선택한다. 대표 사례 통과는 전체 방송의 정확도를 보장하지 않는다.

실제 AI 호출 재현은 `node scripts/verify-seller-logic-codex-ai.mjs 2 --key-file scratch/seller-logic-api-keys.local`로 수행한다. Supabase 관리 API 키 JSON과 `.env.local`이 필요하며 유료 제공자를 호출한다. 관리자 경계는 로컬 검증용으로 대체하고 적용 슬롯·키·모델·제공자는 실제 값을 읽는다. Soniox 검증은 `scripts/verify-soniox-live.mjs`에 `--purchase-only true`를 추가한다. 검증 키 파일은 커밋·배포하지 않는다.
