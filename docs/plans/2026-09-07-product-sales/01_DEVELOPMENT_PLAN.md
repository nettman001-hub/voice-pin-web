## 1 목표와 이번 개발 범위

판매자는 상품번호 또는 상품명과 상품사진으로 상품을 등록하고, 해당 상품의 구매자를 음성 또는 Android 댓글 선택으로 확정한다. 웹과 Android는 같은 회차, 현재 상품, 판매금액, 구매자 목록을 보여준다. 판매를 확정하거나 수정하면 지정 PC에서 원본 전표 또는 정정 전표가 출력된다.

이번 우선 개발은 기존 웹앱과 Android 앱의 기능 확장이다. 별도 Windows 통합 앱 제작 방향은 00_WINDOWS_PROPOSAL.md에 보관하며 이번 작업에 섞지 않는다. 다만 Android 판매의 전표 출력을 위해 기존 Windows 댓글 도우미의 기능 확장은 필요하다.

이 문서는 개발할 기능을 설명한다. 문서 작성 시점에 새 상품 중심 기능, API, DB 테이블이 구현되어 있다는 뜻은 아니다. 최초 설계의 소스 기준은 main의 0414e3b였고 단일 에이전트 실행안 개정 기준은 main의 ad97ca2다. 작업을 시작할 때 현재 HEAD와 원격을 다시 확인하며 제품 검증 기록과 새 기능 인수 테스트를 구분한다.

## 3 사용자 확인을 받은 두 가지 결정

첫째, 같은 구매자가 작성한 댓글 여러 개를 선택하면 한 구매자로 합친다. 기본 구매수량은 1이며 판매자가 수량을 수정할 수 있다. 예를 들어 철수의 댓글 두 개를 눌러도 철수의 상품이 두 개로 계산되지 않는다. 수량 입력에서 2로 바꾸었을 때 두 개가 된다.

둘째, 이미 판매된 상품의 가격을 수정하면 기존 구매자의 판매금액에도 적용한다. 최종 저장 전에 영향받는 구매자, 수량, 이전 금액, 새 금액, 총 증감액을 보여준다. 사용자가 확인한 범위가 다른 기기 변경으로 달라지면 다시 확인한다.

두 결정은 전체 문서의 고정 조건이다. 아래 기본안이나 개발자 편의로 변경하지 않는다.

## 4 초보 개발자를 위한 데이터 이해

상품은 판매할 물건이고, 판매는 누가 그 물건을 몇 개 샀는지를 기록한 행이다. 상품만 등록한 상태에는 아직 구매자가 없으므로 매출도 전표도 생기지 않는다.

예를 들어 상품 123번 니트의 단가가 20,000원이고 철수가 두 개, 영희가 한 개를 샀다면 상품은 한 개의 등록정보, 판매는 구매자별 두 행, 판매수량은 세 개, 판매금액은 60,000원이다. 상품 목록의 행 수와 실제 판매수량은 다르다.

상품번호와 사진은 화면에서 찾는 기준이다. 내부 연결은 productId라는 변경되지 않는 ID를 사용한다. 상품번호를 123에서 124로 고쳐도 productId가 같으므로 기존 구매자와 판매 연결이 유지된다. 사진 URL은 만료되거나 바뀔 수 있어 키로 사용하지 않는다.

구매자는 닉네임으로 보여주지만 TikTok user ID 등으로 구별한다. 이름이 같은 다른 사람을 합치지 않고, 이름을 바꾼 같은 사람은 확인된 ID를 통해 기존 구매통계와 연결한다.

## 5 전체 동작 구조

```text
웹 음성 입력 ── 상품 후보와 판매 후보 ──┐
                                      ├─ 인증된 공통 판매 API ─ DB와 상품사진
Android 상품등록과 댓글 선택 ──────────┘              │
                                                   ├─ 웹과 Android 목록 갱신
TikTok 댓글 ─ PC 댓글 수집 ─ 클라우드 댓글 저장 ────────┤
                                                   └─ 전표 작업 큐 ─ PC 도우미 ─ 프린터
```

휴대폰에서 localhost 주소로 PC에 접속하는 구조를 만들지 않는다. Android는 기존 기기 페어링을 통해 HTTPS 서버 API에 접속한다. 댓글 수집과 실제 출력은 PC 도우미가 맡고, 상품과 판매의 원본은 같은 workspace의 클라우드 DB로 통합한다.

PC가 꺼져도 Android에서 상품과 판매 저장은 가능하지만 새 댓글 수집과 실제 전표 출력은 대기한다. 이 두 상태를 화면에 따로 보여준다. 클라우드 연결이 끊겨 서버 저장을 확인할 수 없으면 임시 입력을 보존하되 판매완료로 표시하지 않는다.

PC 도우미는 작업을 가져온 뒤 실제 Windows 인쇄 호출 직전에 서버에 `SUBMITTING`을 먼저 기록하고, 그 성공을 확인한 경우에만 프린터 시스템으로 보낸다. 이 경계의 응답이나 실제 접수 여부가 불명확하면 자동으로 다시 인쇄하지 않고 확인 필요로 표시한다. 판매 저장의 한 번 처리와 물리 용지의 정확히 한 번 배출은 같은 보장이 아니므로 상태를 분리한다.

## 6 판매자 설정

설정은 웹과 Android에서 공유한다. 메뉴 이름 기본안은 판매 설정이며 상품등록, 상품사진 촬영과 등록, 상품명 입력의 세 항목을 둔다. 음성 명령 단어와 팝업 시간도 이곳에서 관리한다.

| 상품등록 | 사진 | 이름 | 결과 |
| --- | --- | --- | --- |
| OFF | 무관 | 무관 | 기본안은 기존 판매모드 유지. 신규 상품등록 UI와 명령 비활성 |
| ON | ON | ON | 이름 또는 번호와 가격 입력, 상품 촬영과 등록 |
| ON | ON | OFF | 이름 입력 없이 자동번호 발급, 촬영사진과 가격 등록 |
| ON | OFF | ON | 이름 또는 번호와 가격 등록, 번호이미지 생성 |
| ON | OFF | OFF | 자동번호와 번호이미지 및 입력 가격으로 등록 |

사진 기능 OFF이면 카메라 권한과 화면공유 권한을 요청하지 않는다. 이름 기능 ON이어도 입력을 비워둘 수 있으며 자동번호로 보완한다. 가격 미입력은 임의의 숫자로 보완하지 않는다. 가격 없는 상품 초안은 보관할 수 있지만 판매 확정은 가격 입력 뒤에 가능하다.

기능 OFF의 세부 동작은 기존 흐름을 유지하기 위한 구현 기본안이다. 신규 상품 기능은 테스트 workspace에서 먼저 켜고 검증 후 판매자에게 제공한다. 설정 변경 시 이미 진행 중인 후보는 이전 설정으로 조용히 저장하지 않고 최신 설정으로 재검증한다.

## 7 웹 음성 상품등록

### 7 1 판매자가 보는 흐름

1. 판매자가 상품영역을 화면공유로 선택하고 음성 청취를 시작한다.
2. 예를 들어 상품등록 상품번호 123 금액 이만원 상품캡처라고 말한다.
3. 앱은 상품등록 후보 하나를 만들고 123번, 캡처사진, 20,000원을 팝업으로 보여준다.
4. 팝업에 자동 저장까지 남은 시간을 표시한다. 기본 2.5초 동안 취소하거나 내용을 수정할 수 있다.
5. 시간이 끝나면 팝업을 닫고 서버 저장을 요청한다. 현재 상품 영역에 저장 중 상태를 표시한다.
6. 서버 저장 성공 후 해당 상품을 현재 상품으로 확정한다. 실패하면 오류와 재시도 버튼을 표시하고 입력을 보존한다.

웹 상품사진은 기존 화면공유 기능에서 지정한 상품영역을 캡처하는 기본안이다. Android는 전면 카메라를 사용한다. 웹에서 PC 카메라로 상품을 촬영하는 기능은 이번 기본 범위에 포함하지 않는다. 기존 댓글 증빙용 캡처 영역과 상품사진 영역을 별도 설정으로 두어 댓글 화면을 상품사진으로 잘못 저장하지 않게 한다.

### 7 2 여러 문장으로 말하는 경우

상품등록을 말하면 초안을 연다. 이어서 상품번호 123, 금액 이만원, 상품캡처처럼 나누어 말해도 같은 초안에 정보를 채운다. 상품번호 또는 상품명 명령으로 시작한 경우에도 초안을 열 수 있다. 등록 초안이 없는 상태의 단독 금액 발화는 상품이나 판매를 임의 생성하지 않고 필요한 명령 안내를 표시한다.

상품캡처는 초안이 있으면 그 초안의 사진을 채우고 없으면 새 상품 초안을 만든다. 이미 저장된 상품사진을 조용히 덮어쓰지 않는다. 기존 상품 수정은 명시적 수정 화면으로 진입한다. 사용자 정의 명령은 같은 의미의 위 동작에 매핑한다.

사진 사용 설정이 ON이면 캡처 완료, 가격 유효성 확인, 이름 또는 자동번호 준비가 모두 끝나야 2.5초를 시작한다. 정보가 부족하면 보완 대기 상태이며 자동 저장하지 않는다. 마지막 입력 뒤 10초 동안 보완이 없으면 자동 실행을 중단하고 초안을 보류하는 기본안을 둔다. 사용자 입력을 삭제하지 않는다.

### 7 3 개발자가 지킬 처리 순서

모든 STT 공급자는 확정된 전사 이벤트를 하나의 공통 명령 처리기로 보낸다. 현재 Soniox 누적 처리와 다른 공급자의 최종 전사 처리를 각각 저장하게 두지 않는다. 중간 전사는 안내에만 쓰고 같은 최종 발화가 여러 번 도착해도 후보와 저장은 한 번만 만든다.

처리 우선순위는 명시적 수정 상태, 상품 명령, 판매 명령, 일반 발화 순이다. 상품번호 123의 숫자를 123원 판매로 잘못 읽거나 상품등록 문장을 구매자로 해석하면 안 된다. 사용자 명령어 정규화, 한국어 금액 변환, 상품명과 구매자 추출은 독립 함수로 만들어 테스트한다.

후보 상태는 COLLECTING, PREVIEW, COMMITTING, SAVED, NEEDS_INPUT, FAILED, CANCELLED로 구분한다. 타이머는 후보 ID와 generation을 함께 확인한다. 취소, 로그아웃, 회차 종료, 다른 후보로 교체되면 이전 타이머가 저장하지 못하게 한다. 후보를 수정하는 동안 시간을 멈추고 검증 완료 후 2.5초를 다시 시작한다.

빠르게 연속된 상품과 판매 발화는 후보별 큐에 보존한다. 새 상품 저장이 진행 중일 때 받은 구매확정은 그 상품 초안에 연결해 대기시키고, 상품 저장 성공 후 상품 ID와 가격을 고정한 판매 미리보기를 보여준다. 상품 저장 실패 시 뒤따른 판매도 자동 확정하지 않는다. 무조건 이전 활성 상품에 붙이는 구현은 금지한다.

## 8 웹 음성 판매등록

현재 상품이 준비된 뒤 판매완료 닉네임 철수 또는 구매확정 닉네임 철수라고 말하면 구매자, 상품번호, 수량 1, 단가와 합계를 2.5초 보여준다. 닉네임 철수처럼 구매자 명령 자체로 시작한 경우도 현재 상품이 유효하고 구매자 식별이 가능하면 같은 판매 후보를 만든다.

현재 상품 가격이 기본 판매 단가다. 판매자가 예고하지 않은 새 금액을 같은 문장에 말하면 기존 상품 가격을 자동으로 일괄 수정하지 않는다. 금액이 다르다는 확인 상태로 보내고 상품 가격 수정 절차 또는 올바른 상품 선택을 안내한다. 이 규칙은 가격 변경이 모든 기존 구매자에게 영향을 주기 때문에 필요하다.

구매자 이름이 최근 댓글의 두 사람 이상과 일치하면 자동 확정을 멈추고 선택을 요청한다. 구매자를 전혀 식별할 수 없으면 입력 보완 상태로 둔다. 판매자는 검색된 확인 구매자를 고르거나, 후보가 없음을 확인하고 이번 판매부터 사용할 수동 구매자를 만들 수 있다. 닉네임만으로 과거 구매이력을 자동 병합하지 않는다. 자동완료 시간은 유효한 정보가 완성된 뒤 시작한다.

서버 저장 성공 시 웹 자동 적재 목록과 Android 판매 목록이 갱신되고 전표 작업이 생성된다. 저장 중, 판매 저장 완료, 전표 대기, 인쇄 시스템 접수를 구분한다. 팝업 종료를 저장 성공이나 실제 종이 출력으로 간주하지 않는다.

## 9 Android 판매관리 화면

기존 문자연동 화면과 별도로 판매관리 탭을 추가한다. 기존 SMS 권한을 거절하거나 기본 문자 앱으로 지정하지 않은 사용자가 판매관리 자체를 쓸 수 있도록 권한 흐름을 분리한다.

```text
판매관리                         문자연동

이번 회차 5개  100,000원            신규 상품등록
회차 이름 · 댓글 연결 상태 · 전표 연결 상태

상품 123번 니트          [상품사진 또는 번호이미지]
가격 20,000원                         상품 바꾸기

최신 댓글
[선택] 철수 · 저요          이번 회차 2개 40,000원
                           누적 5회 120,000원
                           등록 후 예상 4개 80,000원
[선택] 영희 · 구매할게요     이번 회차 0개 0원
                           누적 0회 0원

선택 구매자 철수 수량 2   영희 수량 1
선택 합계 3개 60,000원
                         판매등록완료

이번 회차 판매내역                            수정
123번 니트  3개 60,000원  구매자 2명  전표 대기
```

위 배치는 요구사항을 구체화한 기본 와이어프레임이다. 수치는 설명용이며 실제 목록의 선택 체크 상태와 합계는 함께 갱신해야 한다. 작은 화면에서는 누적 정보를 두 줄로 표시하고 댓글 본문이 합계 숫자를 밀어내지 않게 한다. 하단 판매등록완료 버튼은 키보드와 시스템 내비게이션 영역에 가려지지 않도록 한다.

댓글은 최신순이다. 새 댓글이 도착해도 이미 선택한 구매자와 수량을 유지한다. 사용자가 과거 댓글을 읽고 있으면 스크롤을 강제로 맨 위로 옮기지 않고 새 댓글 알림을 보여준다. 같은 구매자의 여러 댓글을 선택하면 선택 구매자 영역에는 한 줄만 표시하지만, 근거에는 사용자가 실제로 누른 댓글 ID만 담는다. 같은 구매자의 누르지 않은 댓글까지 자동 선택하거나 판매 근거로 넣지 않는다.

현재 상품이 다른 기기에서 바뀌면 상품 카드만 바꾸고 기존 선택을 새 가격으로 자동 결제하지 않는다. 기존 선택의 상품명과 가격을 고정해 보여주고 재선택 또는 최신 상품으로 적용을 확인한다. 실제 제출 시에도 서버가 상품과 회차 revision을 검증한다.

## 10 Android 상품등록과 촬영

1. 신규 상품등록을 누르면 상품명 또는 상품번호와 가격 폼을 연다. 숫자만 입력한 번호는 문자열로 취급해 `00123`의 선행 0을 보존하고, 일반 문구는 상품명과 자동번호로 처리한다.
2. 이름 입력 설정이 OFF면 이름 입력칸을 숨긴다. 가격에는 숫자 키보드와 원 단위를 사용한다.
3. 확인을 누르면 입력을 검증하고 서버에서 draft와 중복 없는 번호를 준비한다.
4. 사진 설정이 ON이면 전면 카메라 권한과 준비 상태를 확인한다.
5. 촬영 준비가 끝난 뒤 2, 1 카운트다운을 보여주고 사진 한 장을 자동 촬영한다.
6. 사진을 올리고 상품등록 완료를 요청한다. 서버 성공 후 현재 상품 카드와 웹을 갱신한다.

처음의 권한 응답과 카메라 초기화 시간은 기기마다 다르므로 확인 버튼 클릭 후 언제나 정확히 2초에 찍힌다고 구현하지 않는다. 준비 완료 후 보이는 카운트다운 2초를 보장한다. 화면 밖으로 나가거나 취소하면 타이머와 카메라를 정리한다. 후면 카메라로 임의 대체하지 않는다.

사진 기능 OFF이면 카메라 단계를 건너뛰고 번호이미지를 저장한다. 사진 기능 ON인데 카메라가 없거나 거부되면 재시도, 취소, 번호이미지로 등록 선택지를 제안한다. 번호이미지 사용은 사용자가 직접 고른 경우에만 적용하고 촬영 성공으로 표시하지 않는다. 이때 새 상품 초안을 만들지 않고 기존 초안의 번호 예약을 유지한 채 대체 방식만 변경한다.

이름과 사진이 모두 없더라도 서버 번호와 그 번호의 이미지를 저장한다. 이름이 없다는 이유로 이전 상품명을 복사하지 않는다. 가격이 비어 있으면 가격 입력을 요청한다. 촬영사진은 숫자와 글자가 정상 방향으로 보이는지 좌우 반전과 회전을 확인한다.

## 11 댓글 선택 판매등록과 계산

댓글의 체크는 해당 구매자를 선택하는 동작이다. 같은 구매자의 댓글 두 개는 한 명이며 수량은 1이다. 수량 변경은 선택 구매자 영역에서 명시적으로 한다. 등록 버튼에는 선택한 구매자 수, 전체 수량, 전체 금액이 보이도록 한다.

예를 들어 이번 회차의 이전 상품 판매가 2개 40,000원일 때, 현재 상품 20,000원을 철수 2개와 영희 1개로 선택하면 선택 합계는 3개 60,000원이고 등록 후 회차 합계는 5개 100,000원이다. 저장 전에는 예상값이고 서버 성공 후 확정값이다.

판매등록완료 버튼을 누르면 productId, 상품 revision, sessionId, 회차 revision, 구매자 ID와 수량 및 operationId를 한 묶음으로 고정한다. 네트워크가 느려도 버튼 연타로 새 operationId를 만들지 않는다. 응답을 못 받은 경우 get-operation으로 결과를 확인한다. 서버에 기록이 없다는 NOT_FOUND이면 보존한 원래 본문을 같은 operationId로 재전송하며, 새 ID로 같은 판매를 만들지 않는다.

등록 성공 후 선택을 해제하고 판매내역을 갱신한다. PC 도우미가 꺼져 있어도 판매 저장은 성공할 수 있고 전표는 대기로 남는다. Android가 직접 프린터 명령을 보내는 기능은 이번 범위에 포함하지 않는다.

## 12 상품 중심 판매내역 수정

Android 판매내역의 우측 수정과 웹 대시보드 자동 적재 목록의 수정은 같은 순서를 제공한다. 웹 전체 판매내역 화면에서도 같은 편집기를 재사용한다.

1. 수정 버튼을 누른다.
2. 이번 회차에 판매등록완료된 상품 목록을 보여준다.
3. 상품을 선택하면 상품번호 또는 이름, 사진, 가격과 구매자별 수량 및 금액을 보여준다.
4. 상품 정보를 바꾸거나 구매자를 추가, 제외, 교체하고 수량을 바꾼다.
5. 변경내용 확인을 누르면 서버가 변경 전후와 영향을 계산해 보여준다.
6. 판매자가 완료를 누르면 한 번의 처리로 상품과 판매 및 수정 이력과 전표 작업을 저장한다.
7. 양쪽 화면의 판매내역과 회차 및 누적 통계를 갱신한다.

가격을 20,000원에서 25,000원으로 바꾸면 이 상품의 기존 활성 판매에도 적용한다. 철수 2개는 40,000원에서 50,000원, 영희 1개는 20,000원에서 25,000원으로 바뀐다. 영향은 구매자 2명, 수량 3개, 합계 60,000원에서 75,000원, 증액 15,000원이다. 이전 다른 상품의 판매 40,000원은 그대로이므로 회차 합계는 115,000원이다.

변경 전에 다른 기기가 판매를 추가하거나 수량을 바꾸었다면 기존 미리보기로 저장하지 않고 최신 영향목록을 다시 보여준다. 변경한 내용이 없으면 수정 이력이나 전표를 늘리지 않는다.

이미 인쇄 시스템에 접수된 판매의 변경은 원본과 연결된 정정 전표를 추가한다. 신규 구매자 추가는 신규 전표, 구매자 제외는 취소 전표를 만든다. 아직 실행되지 않은 구판 출력은 취소하고 최신판으로 대체할 수 있다. 정정 전표가 출력되었다고 판매행을 새로 추가하지 않는다.

상품사진 변경은 수정 팝업의 임시 미리보기에만 먼저 반영하고, 서버가 발급한 수정 전용 업로드 경로에 전송한 뒤 변경 영향 미리보기에 포함한다. 사용자가 취소하면 상품 원본은 바뀌지 않는다. 구매자를 추가하거나 바꾸는 경우도 검색과 명시 확인을 거치며 닉네임만으로 기존 기록을 합치지 않는다.

판매용 기기 권한과 출력 대상은 웹 관리자 화면에서 설정한다. 기존 SMS 기기는 판매 읽기·쓰기 권한을 자동으로 받지 않는다. 판매관리 기기, 댓글 수집 PC, 출력 PC의 권한을 따로 보여주고 출력 대상 변경 이력을 남긴다. Android에서 권한이 없으면 관리자에게 권한 요청 안내만 보여주며 반복 재시도하지 않는다.

이미 보낸 정산서, 입금기록, 배송 연결이 있는 경우 변경 영향을 표시하고 재확인이 필요함을 남긴다. 기존 발송 문자와 입금 증빙을 소급 덮어쓰거나 자동 재발송하지 않는다.

## 15 기존 데이터 이전과 배포

기존 sales ID, 금액, 날짜, 구매자명과 연결 정보를 유지한다. 기존 행의 quantity는 1, unit_price는 기존 amount로 채우고 productId는 추측해서 연결하지 않는다. 상품명이 같거나 사진이 같아도 서로 다른 상품일 수 있다. 구기록은 미분류 이전 내역으로 조회 가능하게 둔다.

새 테이블과 nullable 컬럼을 먼저 추가하고 기존 기능이 동작하는지 확인한다. 다음으로 새 API, 업데이트된 PC 도우미, 웹, Android를 준비한다. 테스트 workspace에서 상품 기능을 켜고 확인한 뒤 순차 적용한다. 상품모드가 켜진 작업공간은 구버전 쓰기 요청을 구별해 이중 저장·이중 인쇄를 차단해야 한다.

main push는 웹 배포와 연결될 수 있으므로 실제 배포 작업은 준비된 변경과 테스트 증거를 검토한 뒤 수행한다. Supabase migration과 Edge Function 배포는 Vercel 배포와 별개다. Android APK와 도우미 설치 파일도 각각 배포해야 한다. 단순히 웹 빌드 성공으로 전체 배포 완료를 선언하지 않는다.

문제 발생 시 상품 기능의 신규 쓰기만 끄고 기존 데이터와 출력 상태를 보존한다. 스키마를 삭제하거나 새 판매기록을 지우는 복구 방식을 사용하지 않는다. 이미 PC 인쇄 시스템에 접수된 전표는 앱 rollback으로 회수할 수 없음을 작업 기록에 남긴다.

## 16 구현 기본안으로 기록한 항목

아래는 사용자 확정사항과 구분하여, 장시간 작업 중 에이전트가 서로 다른 가정을 적용하지 않도록 제안한 기본값이다. 구현 착수 전에 바꾸면 공통 명세와 테스트 기대값을 함께 고친다.

- 상품등록 OFF는 구형 판매모드 유지, 새 상품 기능 ON은 상품 ID 필수.
- 웹 상품사진은 기존 화면공유의 별도 상품영역을 사용.
- 팝업 기본 2.5초, 카메라 준비 완료 후 2초 촬영.
- 작업공간당 진행 중 회차 하나와 현재 상품 하나.
- 총 누적구매횟수는 활성 판매 등록 행 수, 구매갯수는 수량 합계.
- 금액 미입력은 보완 요청, 무료 판매와 가격 추정은 1차 범위 제외.
- Android 단독 TikTok 수집과 Android 직접 프린터 출력은 1차 범위 제외.
- 상품명과 사진 변경은 현재 회차의 연결 판매 표시에도 반영하되 이전 이력을 보존.
- 카메라 실패 시 번호이미지는 판매자가 선택한 경우에만 대체.
