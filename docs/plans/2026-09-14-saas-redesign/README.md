# VoiceCAP SaaS 재설계·개발 지시 문서

사용자가 확정한 최신 조건을 반영한 문서다. 기존 웹 UI 재사용을 기술 선택의 전제로 삼지 않되, 이미 운영·시험 중인 계정, 거래 데이터와 Android 앱 업데이트 호환성은 보존한다.

5. [라이브·고객 이력·키핑 최신 상세 계약](C:/dev/voicecap-win/docs/ui-2026-09-14/04_KEEPING_AND_LIVE_V2.md): 고객 네 통계, 결제 상품 보관/합배송, 중복 출고 방지, 보류 전표 출력. K00~K08 작업과 KV01~KV18 추가 인수시험.

작업지시서는 T00–T21의 22개 작업, 인수시험은 65개 시험으로 구성했다. 작업마다 선행 조건·구현 순서·수정 위치·완료 조건을 연결했다. 문서의 로컬 링크·번호·요구사항 연결·JSON 예제는 검사했으며 실제 제품 시험 상태는 모두 미실행이다.

## 이번에 확정한 조건

- 전체 판매 방송의 확정 전사 문장을 클라우드에 보관한다. 판매로 판단된 문장만 저장해서는 안 된다.
- 댓글에 발생 시각·수집 시각·서버 저장 시각과 시간 출처를 보관한다.
- 현재 출시 대상 STT는 Soniox다. 로컬 Whisper는 보류하고 새 앱의 기본·대체 엔진으로 설치하지 않는다.
- Qwen 계열 STT는 후속 개발 대상으로 둔다. 이번에는 공급자를 추가할 수 있는 인터페이스만 마련한다.
- Android는 사용자 확인 기준 Google Play 승인 및 비공개 배포·실기기 테스트를 마친 기존 앱이다. 신규 승인 확보를 선행 과제로 되돌리지 않는다.
- Android 업무폰 자체에서 문자를 읽고 직접 답장할 수 있어야 한다. 문자 실행·업로드 기록은 기기 DB에 영속 저장한다.
- 같은 판매자 계정으로 여러 Windows PC를 사용한다. 방송 수집·실시간 판매 입력은 지정 PC 한 대가 담당하고 다른 PC는 판매·문자·정산·배송을 관리한다.
- 클라우드 PostgreSQL이 공유 업무의 기준이며, PC SQLite와 Android Room은 미전송 기록·캐시·실행 복구를 담당한다.
- 댓글의 고객정보는 구매횟수·누적 구매금액·미이행 횟수·키핑 여부다. 단골/첫구매 등급 표시는 제외한다.
- 키핑은 결제된 미출고 상품을 보관했다가 추가 결제 상품과 합배송하는 별도 업무다. 판매 보류와 구분하고 서버에서 수량을 원자 배정한다.
- 등록된 확정·보류 판매 모두 최초 전표 출력 대상이다. 보류→확정만으로 자동 중복 출력하지 않으며 보류는 청구 대상에서 제외한다.

## 문서의 효력과 실제 상태

이 세부 문서가 이전 [다중 기기 제안](C:/dev/voice-pin-anti/docs/proposals/2026-09-14-multidevice-saas.md)의 상충하는 제안을 대체한다. 특히 Whisper 출시 포함, Android 최초 승인 미확보 전제는 사용하지 않는다.

Play 승인·비공개 테스트 완료는 사용자 제공 사실이다. 소스에서 확인한 Android 값은 applicationId `shop.voicecap.smsbridge`, namespace `com.voicecap.sms`, versionCode `7`, versionName `1.3.3`, minSdk `26`, compileSdk `35`, targetSdk `36`이다. Play에 등록된 최고 versionCode와 실제 서명 설정은 소스 값과 다를 수 있으므로 배포 준비 때 대조한다.

본문의 새 API, DB 테이블, C# 프로젝트, Kotlin 클래스, 시험은 앞으로 만들 대상이다. 이번 작업에서 앱 코드·운영 DB·배포를 변경하거나 실제 SMS·프린터 시험을 실행하지 않았다.
