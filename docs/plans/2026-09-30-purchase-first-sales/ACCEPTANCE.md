# 구매요청 기반 자동 적재 인수·장애 검증 명세

작성일: 2026-09-30. [설계 본문](./DESIGN.md)의 완료 기준이다.

**아래 항목은 전체 목표의 인수 명세이며, 현재 모두 구현되거나 통과했다는 뜻이 아니다.** 구현·검증 범위는 [구현 상태](./IMPLEMENTATION_STATUS.md)에 기록한다.

## 1. 공통 시험 조건

- 테스트 workspace W1/W2, 방송 S1/S2를 분리한다. 동일 표시명이어도 실제 계정 ID가 다르면 다른 구매자다.
- 상품 가격은 사전 등록하지 않으며 초기 가격은 null이다. 별도 언급이 없는 매칭/저장 시험에서는 판매자가 해당 구간에서 `이 상품 만 이천 원이에요`(A), `다음 상품 이만 원이에요`(B)라고 안내한 확정 발화를 근거로 제공한다. 상품·음성 가격의 버전/적용 시각을 명시한다. 사전 가격 안내가 없는 시험은 해당 판매 확정 발화에서만 가격을 확보해야 한다.
- 별도 언급이 없으면 구매 수량 기본값은 1, 상품 필수 옵션은 없고 서버·AI·댓글 수집은 정상이다.
- 긍정 사례의 판매자 문장은 완결된 확정 전사로 제공한다. 부분 전사를 성공 근거로 대신하지 않는다.
- `요청`, `배정 초안`, `서버 확정 판매`, `출력 작업`의 개수를 각각 관찰한다.
- 자동 연결 긍정 사례는 수동 선택 없이 성공해야 한다. 모든 사례를 보류로 보내는 구현은 합격이 아니다.
- 자동 저장은 서버 ACK까지 확인한다. 로컬 행 생성이나 mock helper 통과만으로 성공 판정하지 않는다.
- 보류/비판매/거절 사례는 확정 매출·구매자 합계·출력에 영향이 없는지 확인한다.
- 제시한 숫자 시간창이나 self-reported confidence가 아니라 근거·결과를 검사한다.

## 9. 자동화 수준과 테스트 구성

1. 순수 함수: 댓글 의도, 호칭 가설, 숫자 충돌, 가격 의미, 상태 reducer, 엄격한 AI schema.
2. 이벤트 재생: 확정 조각·지연 댓글·상품 전환·정정·AI 결과를 순서/지연 조합별 재생. 허용되는 사건 순서 교환에서 같은 최종 결과인지 확인.
3. 성질 기반 검사: 같은 source/operation 재처리는 멱등, 요청 명시 수량 초과 없음, 충돌 숫자 자동 연결 없음, 다른 workspace 접근 없음, 철회된 요청이 늦은 AI로 부활하지 않음.
4. 실제 DB 통합: 트랜잭션 rollback, UNIQUE 제약, CAS, lease와 expired attempt, source 근거 연결, API 권한.
5. UI 종단간: 실제 댓글 수신 인터페이스와 STT 공통 이벤트를 사용해 요청→검토→서버 ACK→합계/출력 job을 확인.
6. 녹음/전사 평가: 허가된 실제 방송 자료를 별도 평가 세트로 분리. 프롬프트/규칙 튜닝에 사용한 자료와 출시 확인 자료를 섞지 않는다.

자동 테스트에서 AI 응답 fixture를 사용하는 것은 저장 검증의 재현성을 위한 것이다. fixture 성공을 실제 모델의 한국어 해석 정확도로 보고하지 않는다. 실제 AI 출력 평가와 저장 계층 테스트를 둘 다 수행한다.

## 10. 운영 평가와 승인 기록

- 규칙 경로와 AI 경로의 잘못된 구매자·가격·상품·중복·판매 누락·보류 비율을 각각 측정한다.
- STT 지연, 댓글 지연, 앱 판정 지연, AI 처리 지연, 서버 ACK 지연을 분리해 p50/p95를 기록한다.
- 자동 반영 전 검증 모드의 제안을 판매자가 확인한 정답과 대조한다. 단순 모델 자기 확신을 정답으로 사용하지 않는다.
- 사용자의 대표 네 가지 긍정 사례(P02, N01, N02, N03)는 실제 자동 경로에서 성공해야 한다.
- 준비한 필수 평가 세트에서 잘못된 구매자/상품/근거 없는 가격/중복이 발견되면 수정하거나 해당 자동 유형을 차단하고 재실행한다.
- 출시 승인서에는 세트 크기·기간·규칙/모델/프롬프트 버전·실행 환경·미해결 실패·제외한 자동 유형·rollback/중단 담당을 기록한다. 테스트에서 0건 오류였다는 사실을 미래 100% 보장으로 홍보하지 않는다.
- 기존 실패와 신규 회귀를 구분한다. 설계 문서 작성만으로 build/test/deploy 통과를 주장하지 않는다.
