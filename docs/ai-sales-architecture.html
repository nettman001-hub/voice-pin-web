판매 적재 & AI 개입 파이프라인 시각화

음성 발화(STT) ➜ 규칙 우선 해결(Rule-First) ➜ 2중 슬롯 AI 장애대응 ➜ 서버 교차 검증 ➜ 감열식 영수증 인쇄

1 단일 판매 적재 라이프사이클 (End-to-End Visual Map)

음성 발화가 들어왔을 때 규칙과 AI가 어떻게 분담하고 데이터베이스에 최종 확정되는지 보여줍니다.

1

초저지연 Fast-Track

완전한 발화는 2초 카운트다운 후 즉시 자동저장되어 0.1초 만에 영수증 프린터로 전송됩니다.

2

비용 0원 규칙 우선

단순 끝번호 일치나 상품 단가 누락은 사전에 정의된 결정론적 규칙으로 먼저 해결하여 AI 호출 비용을 아낍니다.

3

불변 근거와 감사 추적

AI가 해결한 모든 판매는 원본 발화, 댓글 스냅샷, 바뀐 이유가 history에 영구 기록됩니다.

2 6대 판매 보류 사유 및 해결 전략 매트릭스

판매 발화에서 데이터가 불완전할 때 시스템이 감지하는 6가지 표준 코드와 규칙 및 AI의 역할 분담입니다.

MISSING_NICKNAME 우선순위 High

구매자 닉네임 미추출 / 미확인

발화에서 "구매자", "이분", "손님" 등으로 말하거나 닉네임이 STT에서 누락된 경우.

규칙 처리:직전 단일 댓글 작성자 대조
AI 역할:최근 10개 댓글의 문맥("저요", "구매") 분석 후 후보 추천
TRAILING_DIGITS_ONLY 규칙 최우선

전화번호 끝 4자리만 감지

"뒷번호 7890님 낙찰이요"처럼 4자리 숫자 식별자만 발화된 경우.

규칙 해결:댓글/구매자 중 유일하게 일치하는 1명 즉시 매칭 (AI 불필요)
AI 역할:동일 번호가 2명 이상일 때 발화 시각과 댓글 시점 차이 분석
MISSING_AMOUNT 자동 연결

판매 금액 누락 또는 0원

금액 언급 없이 "12번 홍길동님 완료"라고만 발화하여 단가가 비어있는 경우.

규칙 해결:현재 방송에 활성화된 상품 단가(unitPrice) 자동 승계
AI 역할:"1.2" 같은 소숫점 구어체를 12,000원으로 정확 파싱
SPLIT_UTTERANCE 후속 발화 결합

분리 발화 (문장 끊김)

"홍길동님..." 하고 잠시 쉬었다가 "15,000원에 드릴게요"라고 두 문장으로 쪼개진 경우.

규칙 처리:후속 발화 연결 시 금액 누락 사유와 함께 동시 해제
AI 역할:조각난 두 발화의 의미적 연결 및 하나의 판매 데이터로 합성
DELAYED_COMMENT 대기 후 자동 해제

댓글 지연 (네트워크 딜레이)

진행자는 화면을 보고 불렀으나, 방송 플랫폼의 댓글 웹소켓이 1~2초 늦게 도착한 경우.

규칙 처리:신규 댓글 유입 시 자동 백그라운드 재대조 트리거
AI 역할:오타가 포함된 닉네임("미니미" vs "minimi") 유사도 매칭
MULTIPLE_CANDIDATES 엄격 가드

복수 후보 충돌 (임의 선택 금지)

"철수님"을 불렀으나 댓글 창에 "김철수", "이철수" 두 명이 동시에 존재하는 경우.

임의 확정 금지:AI나 시스템이 절대 임의로 찍지 않고 보류 유지
해결 방식:판매자 화면에 [후보 2명 선택 모달] 띄워 1클릭 확정 유도

3 이중 슬롯 자동 장애 전환 (Failover) & 서킷 브레이커

로컬 PC 도우미(Ollama/자체 서버)가 죽거나 응답하지 않아도 클라우드 LLM으로 0초 만에 우회 실행합니다.

슬롯 1 ➜ 슬롯 2 자동 전환 메커니즘

슬롯 1 (Primary) : 로컬 / 사내 LLM 기본 호출

Ollama (Qwen2.5:7b) / 사내 도우미 경유

포트 11434 / 2137 ➜ 비용 0원, 데이터 외부 미유출

타임아웃 / PC도우미 종료 / VRAM 부족 발생 시
슬롯 2 (Secondary) : 클라우드 LLM Failover

OpenAI (gpt-4o-mini) / Google (Gemini 1.5 Flash)

서버 전용 Secret 보관 (브라우저에 API 키 미노출)

💡 전환 시 안전 가드: 슬롯 1에서 지연되었던 응답이 뒤늦게 도착하더라도 이미 발급된 시도 ID(attemptId)가 만료(EXPIRED)되어 판매 데이터를 오염시키지 못합니다.

서킷 브레이커 (Circuit Breaker) 상태 규칙

연속 실패 한계 (Fail Threshold) 3회 연속 실패 시 차단
쿨다운 지속 시간 (Cooldown) 60초간 호출 중단 및 우회
자동 복구 조건 (Recovery) 2회 연속 성공 시 CLOSED 복귀

동시성 잠금 (Optimistic Revision Lock)

AI가 추론하는 동안(약 1~2초) 판매자가 웹 대시보드에서 해당 판매를 수동으로 수정하거나 확정하면 판매의 revision이 증가합니다 (v1 ➜ v2). 뒤늦게 도착한 AI 응답(v1 기준)은 REVISION_CONFLICT 에러를 뿜으며 즉시 폐기되어 수동 작업을 절대 덮어쓰지 않습니다.

4 AI 환각(Hallucination) 방지 & 5단계 방어선

LLM의 허위 닉네임 생성이나 엉뚱한 금액 추천을 서버가 어떻게 100% 필터링하는지 설명합니다.

방어선 1

실존 댓글 / 구매자 교차 대조

AI가 "구매자는 @super_star님입니다"라고 제시하더라도, 해당 방송 회차의 실제 댓글 테이블(comments)이나 구매자 명단(buyers)에 일치하는 닉네임이 없으면 서버에서 즉시 422 AI_VALIDATION_FAILED로 기각합니다.

방어선 2

등록 상품 유효성 검증

AI가 임의로 존재하지 않는 상품 코드(예: "99번")를 추천하는 경우, 현재 방송 세션의 등록 상품 목록에 존재하는지 엄격히 확인합니다. 일치하는 상품이 없으면 적용을 거부하고 보류 상태를 유지합니다.

방어선 3

결제 완료(PAID) 자동 정정 차단

판매자가 음성으로 정정 발화를 하더라도, 이미 고객이 결제를 완료한 판매 건은 자동 복원이나 변경을 엄격히 차단하여 정산 불일치 및 회계 사고를 사전에 차단합니다.

5 실전 발화 시나리오 대화형 시뮬레이터

시나리오를 선택하여 발화가 시스템에서 어떻게 분석되고 최종 판매로 적재되는지 단계별로 확인해보세요.

테스트 발화:

"가격이 0.9가 아니고 1.2입니다"

정정 적용 성공
1. 분석 파이프라인 판단
• 의도: VOICE_CORRECTION (음성 정정)
• 기존 값: 9,000원 (from: 0.9)
• 변경 값: 12,000원 (to: 1.2)
• 범위: THIS_SALE_ONLY (방금 건만)
2. 데이터베이스 & 출력 결과
• 대상 판매: 동일 saleId 유지 (v1 ➜ v2)
• 단가: 9,000원 ➜ 12,000원 정정
• 영수증: [정정] 전표 1회 자동 발행
• 회계 이력: CORRECTION 감사 로그 적재
