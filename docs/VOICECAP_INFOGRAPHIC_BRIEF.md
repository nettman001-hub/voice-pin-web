## 1. 한 줄 소개

**VoiceCAP(보이스캡)은 틱톡 라이브 판매자의 방송 멘트를 AI가 실시간으로 듣고, 댓글과 대조해 판매 내역을 자동으로 기록하는 라이브커머스 판매관리 서비스다.**

- 서비스 주소: `https://www.voicecap.shop`
- 대표 카피(현재 온보딩 화면): "틱톡 라이브 판매 멘트를 듣고, **판매 내역과 댓글 화면을 자동 기록**합니다."
- 핵심 키워드: `구매확정 · 닉네임 · 금액`을 음성으로 인식

## 2. 해결하는 문제

| 판매자의 기존 고충 | VoiceCAP의 해결 |
|---|---|
| 방송 중 "햇살언니 1.5에 드릴게요"라고 말하고 손으로 따로 적어야 함 | 판매 멘트를 음성인식해 **구매자·금액·회차를 자동 기록** |
| 수백 개 댓글 중 누가 "저요"라고 했는지 놓침 | 틱톡 댓글을 실시간 수집해 **구매 댓글과 판매 멘트를 자동 대조** |
| 방송 후 정산·입금 확인·문자 발송·택배 정리를 수작업 처리 | 정산서 문자 발송, **은행 입금 자동 대조**, 택배 발송 관리까지 연결 |
| 주문 증빙이 남지 않음 | "화면 캡처하세요" 한마디로 **댓글창을 캡처해 판매에 첨부**, 전표 자동 인쇄 |

## 3. 작동 원리 (인포그래픽의 메인 흐름도)

```text
① 판매자 방송 멘트 ─▶ ② 실시간 음성인식(STT) ─▶ ③ 판매 멘트 판별
                                                      │
④ 틱톡 실시간 댓글 ──▶ 구매 댓글("저요","ㅈㅇ") ──────┤ 닉네임 대조
                                                      ▼
                          ⑤ 판매 자동 적재 (구매자·상품·금액)
                                │ 근거 부족 시
                                ▼
                          ⑥ "보류" → 규칙 우선 해결 → 안 되면 AI 재판단
                                ▼
                          ⑦ 서버 검증 후 확정 → 전표 인쇄 · 정산 · 문자 · 택배
```

### 대표 사례 (그대로 그림에 써도 되는 예시)

| 고객 댓글 | 판매자 멘트 | 자동 기록 결과 |
|---|---|---|
| 햇살: `ㅈㅇ` | "네, 햇살언니 만 이천 원에 드리겠습니다" | 햇살 · 1개 · **12,000원** |
| 넥스트: `제가 살게요` | "네스트언니 일 점 오에 챙겨드릴게요" | 넥스트 · 1개 · **15,000원** (발음 오차 보정) |
| 이이돌1234: `저요` | "뒷자리1234언니 0.9에 드리겠습니다" | 이이돌1234 · 1개 · **9,000원** |

- 라이브커머스 관행인 **소수점 가격(1.5 = 15,000원)**을 만원 단위로 자동 변환한다.
- 판매자가 부른 호칭("네스트언니")이 아니라 **실제 댓글 계정**으로 저장한다.
- 닉네임이 겹치거나 근거가 부족하면 **임의로 확정하지 않고 "보류"**로 남긴다.

## 4. 서비스 구성: 4개의 구성요소

| 구성요소 | 역할 | 비고 |
|---|---|---|
| **① VoiceCAP 웹앱** (PC·모바일 브라우저) | 라이브 청취, 판매관리, 정산, 관리자 콘솔 | React 웹앱, Vercel 배포 |
| **② VoiceCAP 댓글 도우미** (Windows 설치 프로그램) | 틱톡 댓글 실시간 수집, 영수증·라벨 전표 자동 인쇄, 내 PC GPU 음성인식 | 설치 1회, PC 시작 시 자동 실행, 자동 업데이트 |
| **③ voicecapSMS** (Android 앱, v1.6.2) | 고객 문자 수발신 연동, 은행 입금 알림 수집, 휴대폰 판매관리 | 3탭: 판매관리 / 문자연동 / 입금확인. Android 8.0 이상 |
| **④ VoiceCAP 클라우드** (Supabase) | 판매·댓글 단일 원본 저장, 실시간 동기화, AI 판단 서버 | 판매자별 작업공간 격리 |

연결 관계: 웹앱 ↔ 클라우드 ↔ Android 앱, 웹앱 ↔ (내 PC) 댓글 도우미 ↔ 클라우드, 댓글 도우미 → 프린터

## 5. 주요 기능 (방송 흐름순 3단계 구성 추천)

### 5-1. 방송 전: 준비

- **음성인식 발음 힌트**: 잘 틀리는 상품명·브랜드명을 최대 **50개** 등록해 인식률 보완
- **캡처 영역 스튜디오**: 윈도우 화면(FHD/QHD/4K 기준)에서 댓글창 좌표를 드래그로 지정
- **댓글 도우미 & 장치 설정**: 틱톡 아이디 연결, 프린터 선택(58mm/80mm 영수증, 50×30mm 라벨, A4)
- **휴대폰 연결**: 1회용 연결 코드(10분 유효)로 voicecapSMS 앱 페어링

### 5-2. 방송 중: 라이브 청취 홈 (ON AIR)

- **실시간 음성인식**: 방송 탭 오디오 또는 마이크 → 클라우드 STT(Soniox · Deepgram Nova-3) 또는 **내 PC GPU 무료 STT**(Whisper)
- **실시간 댓글 수집**: 구매 의사 댓글("저요", "ㅈㅇ", "제가 살게요")을 구매요청으로 자동 표시
- **판매 자동 적재**: 판매 멘트 + 댓글 대조 → 판매 카드 즉시 생성
- **음성 명령**: "수정 시작" → "닉네임 영희, 금액 3만원" → "수정 완료" / "방금 건 삭제" / "화면 캡처하세요"
- **자동 캡처**: 캡처 지시와 판매를 **10초** 이내로 자동 짝짓기
- **전표 자동 인쇄**: 확정 판매를 PC 프린터로 무음 출력
- **단골 정보 배지**: 구매자의 이전 구매횟수 · 누적 매출 · 미이행 횟수 표시
- **청취 종료 예약**(최대 24시간), **무음 지속 감지** 경고
- **AI 상태 배지**: 판매 AI 연결 상태 상시 표시

### 5-3. 방송 후: 정산·후속 처리

- **방송 후 일괄 확인**: 보류 건만 모아 검토 후 원클릭 확정
- **판매 내역 목록**: 방송 회차별 필터(예: `2026-10-15 라이브 1회차`), 구매자별 묶어보기
- **판매내역/문자비교**: 판매 목록과 고객 문자함을 한 화면에서 2분할 대조, MMS 사진 확인
- **정산서 관리 & 발송**: 판매 내역 선택 → 청구서 생성 → **휴대폰 문자로 발송**
- **은행 입금 자동 대조**: 휴대폰의 은행 입금 알림 → 금액·입금자명으로 정산서 자동 매칭
  - 지원 은행 9곳: KB국민 · 신한 · 우리 · 하나 · NH농협 · IBK기업 · 카카오뱅크 · 케이뱅크 · 토스
  - 금액만 같은 입금은 자동 확정하지 않음. 한 번 확정한 입금자명은 기억해 다음부터 자동 확정
- **택배발송 관리**: 운송장·발송 문자·배송완료 관리. 택배사 5곳(CJ대한통운 · 우체국 · 한진 · 롯데 · 로젠)
  - 택배비 정책: 고정 부과 / 금액별 조건부 무료 / 전체 무료
  - **고객 키핑(보관)**: 여러 회차 구매분을 보관했다가 묶음배송
- **정산 및 엑셀 다운로드**: 일자별·회차별 집계, CSV 내보내기
- **방송 음성 기록 보관**: 방송 전체 멘트 기록을 클라우드에 보관하고 .txt/.csv로 다운로드(라이브 청취 홈)

## 6. 비즈니스 차별점 (판매자가 얻는 이익 기준)

> 규칙 우선 처리, AI 이중화, 서버 검증 같은 시스템 내부 구조는 판매자가 VoiceCAP을 고르는 이유가 아니므로 차별점으로 쓰지 않는다.

| # | 차별점 | 판매자에게 주는 의미 | 근거 기능 |
|---|---|---|---|
| 01 | **늘 하던 말 그대로** | 따로 입력하지 않아도 평소 판매 멘트가 주문 기록이 된다. "저요·ㅈㅇ", "언니" 호칭, 소수점 가격(1.5 = 15,000원)까지 알아듣는다 | 음성 판매 인식, 구매 댓글 대조 |
| 02 | **구매자는 판매자가 정한다** | 여러 명이 "저요"를 외쳐도 선착순 자동 낙찰이 아니다. 판매자가 "드릴게요" 한 고객에게만 주문이 기록된다 | 구매요청과 판매자 배정 분리 |
| 03 | **상품 등록 없이 바로 방송** | 상품 목록·가격표를 미리 만들 필요가 없다. 말한 가격이 판매가가 되고 상품 번호는 자동으로 붙는다(예: `001-20261015-1회차`) | 음성 가격 확정, 순차 상품번호 |
| 04 | **방송 후 업무까지 한 곳에서** | 주문 → 정산서 문자(판매자 휴대폰 번호로 발송) → 은행 입금 자동 확인 → 택배 발송이 같은 주문 정보로 이어진다 | 정산서, voicecapSMS, 입금 대조, 택배 관리 |

보조 메시지 (차별점 다음 순위):

- **라이브커머스 운영 방식 그대로**: 회차별 정산, 키핑(보관) 묶음배송, 단골·미이행 고객 표시
- **주문마다 근거가 남는다**: 판매 멘트·구매 댓글·캡처 화면으로 고객 문의에 바로 답할 수 있다. 애매한 주문은 확정하지 않고 방송 후 한 번에 확인한다

## 7. 안심 포인트 (판매자 언어로)

- **개인 문자는 휴대폰 밖으로 나가지 않는다**: 주문 고객과 주고받은 문자만 연동한다. 인증번호·개인 문자, 은행 알림 원문·잔액은 보내지 않는다
- **내 고객 정보는 내 계정에서만**: 다른 판매자는 내 판매·고객 정보를 볼 수 없다
- **같은 주문이 두 번 기록되지 않는다**: 네트워크가 불안정해 다시 전송돼도 한 번만 저장된다
- **PC·휴대폰 어디서 고쳐도 바로 반영된다**

## 9. 인포그래픽에 쓰면 안 되거나 주의할 표현

| 항목 | 이유 |
|---|---|
| "0.1초 만에 인식", "100% 정확" | 페이지 메타 설명에 "0.1초"가 있으나 측정 근거가 없음. 설계 문서는 "음성 의미 정확도 100%를 보장하지 않는다"고 명시 |
| "완전 자동 판매" 단독 표현 | 근거가 부족하면 보류 후 판매자 확인을 거침. "자동 기록 + 애매하면 보류"가 정확 |
| "로컬 DB 저장" | 온보딩 화면 문구가 오래됨. 현재 판매·댓글 원본은 클라우드 |
| 고객 관리(모바일·카카오톡) | 메뉴에 있으나 **준비 중**(비활성) |
| 실결제·구독 결제 | 결제 화면은 모의 동작. 실제 PG 연동 없음 |
| 다중 상품 동시 배정, 옵션·묶음 가격 자동 처리 | 확인 대상으로 남기는 범위. 자동 처리 완료 기능 아님 |
| 플랜 설명의 "Deepgram" 고정 표기 | 실제로는 Soniox · Deepgram · 내 PC STT 중 선택. "실시간 AI 음성인식"으로 쓰는 것을 권장 |
| 지원 플랫폼 | 댓글 수집은 **틱톡 라이브 전용**. 다른 플랫폼 지원은 없음 |
| 시스템 내부 구조를 차별점으로 쓰기 | 규칙 우선 처리, AI 이중화, 서버 검증은 판매자가 얻는 이익이 아님. 6장의 비즈니스 차별점을 사용 |
