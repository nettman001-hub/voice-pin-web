PR24 LM Studio 짧은 프롬프트 실제 시험 결과
시험일: 2026-10-20 (Asia/Seoul)
검증 대상 소스 커밋: 97ed1ac (PR #24 squash)
모델 ID: gemma-4-e4b-it
서버: 사용자가 지정한 LM Studio 서버 (공개 파일에는 주소와 인증 정보를 포함하지 않음)

결론
제안한 352자 지침과 대상 거래 정보를 실제 모델에 보내 일부 개선을 확인했다. 그러나 시연·취소·동명이인·복수 가격 오확정과 정상 가격 누락이 남아 이 문구만으로 해결됐다고 볼 수 없다.

전체 집계
- 가상 사례 18개 × 독립 호출 2회 = 36회. 36회 모두 실제 모델 응답 수신.
- 기존 프로그램 후처리까지 기대한 결과: 27/36회. 오처리: 9/36회.
- 보류 대상을 잘못 확정: 7회. 정상 판매를 잘못 보류: 2회.
- 정상 판매 대상: 18/20회 정답. 보류 대상: 9/16회 정답.
- 답변이 두 줄인 경우: 36/36회. 지정한 두 값과 정답까지 모두 맞는 답: 22/36회.
- 27회 정답에는 가격을 읽지 못해 프로그램이 보류한 답도 포함된다. 예: "닉네임: KH / 가격: 없음원". 이 답은 지정한 보류 출력 "닉네임: 없음 / 가격: 없음"과 다르다.

이전 프롬프트와 비교
- 같은 모델 ID의 이전 시험은 26회까지만 수행했으므로 겹치는 26회만 대응 비교했다.
- 겹치는 26회: 이전 정답 18회 → 변경 후 21회. 보류 오확정 5회 → 3회.
- 양쪽 모두 실제 답변이 있는 24회만 비교: 정답 18회 → 20회. 보류 오확정 5회 → 2회.
- 서로 다른 시점의 호출이며, 36회 전체와 이전 26회를 그대로 정확도 비교하지 않았다.

남은 오처리
- 05_fragments 잡담과 가격 끝말이 섞인 조각: 2회
- 11_two_prices 한 거래에 가격 두 개: 1회
- 12_demo 판매가 아닌 보여 드릴게요: 2회
- 13_cancel 명시적으로 취소한 판매: 2회
- 16_same_name 동명이인 두 계정: 2회

길이와 응답 시간
- 지침 문구: 352자. 기본 사례 전체 입력: 기존 347토큰 → 변경 후 403토큰.
- 완료 시간: 최소 6.420초 / 중앙값 10.515초 / 최대 13.080초.
- 이번 36회 모두 4초를 초과했다. 이는 해당 호출 경로·시점에서의 관측이며 모델 자체가 원래 느리다거나 프롬프트가 지연의 유일한 원인이라는 뜻은 아니다.
- thinking 옵션은 보내지 않았다. 실제 응답 36회 모두 추론 토큰 0개.

시험 방법과 범위
- PR24_LM_STUDIO_PROMPT.txt의 지침을 글자 그대로 사용했다. <검토대상>에는 각 판매의 실제 가상 시각·원문을 넣었다.
- 고객 댓글·판매자 멘트 목록은 이전 시험과 글자 단위로 동일하다. 기대 결과와 데이터는 호출 전에 고정했다.
- 원본 selfHostedAdapter를 통해 한 개의 user 메시지와 temperature 0.1을 보냈다. 추가 시스템 메시지·JSON 출력 모드·정답 힌트는 사용하지 않았다.
- API 통신 외피는 OpenAI 호환 규격이며, AI에 전달한 지시와 답변은 평문이다.
- 응답 대기 한도는 60초. 파싱·검증·서버 처리·클라이언트 확정은 기존 코드를 사용했다. 서버 DB는 메모리 대역으로 구성해 실제 모델 응답을 주입했다.
- 제품 프롬프트 생성 코드는 이번 시험에서 바꾸지 않았다. 운영 DB 조회/수정과 실제 프린터 호출은 하지 않았다.
- 검증 테스트: 39개 중 30개 통과, 9개 실패. 실패 9개는 위 오처리 9회를 재현한 것이다.
- 본 문서의 고객명·댓글·판매자 멘트는 전부 가상 데이터다. 계정 ID는 모델용 표에서 제공하지 않는 기존 입력 형식을 유지했다.
