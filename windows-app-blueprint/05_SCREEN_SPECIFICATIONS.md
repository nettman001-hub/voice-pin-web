작성일: 2026-09-26 · 원본 기준: [App.tsx](../src/App.tsx), [웹앱 상세 설계](../docs/replication/02_WEB_DESIGN.md)

> 기존 화면의 접근 경로와 동작을 Windows 앱으로 보존한다. 모바일 전용 하단 메뉴는 Windows 내비게이션으로 바꾸지만 그 메뉴에서 하던 업무는 남긴다. 현재 데모·미연결 기능은 그 사실을 유지하여 옮기고, 실제 상용 기능 완성은 별도 인수 항목으로 관리한다. 아래 `Wxx`는 이 문서의 화면 식별자다.

권한 표시는 공개/판매자/관리자를 기본으로 하며 실제 세부 역할은 서버의 권한 계약을 따른다. 관리자 메뉴를 숨기는 것은 보안 검사가 아니다. 공유 작업공간 자료 읽기·쓰기는 서버에서도 검증한다.

## 2. 공통 화면 계약

모든 데이터 화면은 `initializing / loading / ready / empty / refreshing / offline / forbidden / failed` 상태를 갖는다. 수정 화면은 `clean / dirty / validating / submitting / saved / queued / conflict / unknown / failed`를 추가한다. `queued`는 로컬 전송 대기이며 서버 저장 완료와 다르다.

목록 필터·정렬·스크롤은 화면을 왕복해도 유지한다. 화면 이동 후 전역 녹음·댓글 연결·회차는 유지한다. 컴포넌트가 사라졌다는 이유로 전체 서비스를 종료하지 않는다. 사용자가 로그아웃하거나 작업공간을 바꾸면 해당 범위의 데이터와 민감한 메모리를 안전하게 정리한다.

기본 폼 행동은 라벨, 설명, 값, 인라인 오류, 저장 결과 순서다. 필수 필드는 `필수` 문구 또는 접근 가능한 표시로 전달한다. 서버 오류가 나도 입력 내용은 유지한다. 장시간 요청은 취소 가능 여부와 실제 작업 상태를 분리해 보여 준다.

## 3. 시작·인증 화면

### W01 시작 안내

- 레이아웃: 왼쪽 제품 설명과 실제 작업대 축소 시안, 오른쪽 `시작하기`, `로그인`, `둘러보기`. 세 장 이상의 자동 캐러셀은 쓰지 않는다.
- 소개 기능: 음성 판매 기록, 댓글 구매자 확인, 정산/배송, 내장 댓글·프린터·STT. 작동하지 않는 기능은 완성된 것처럼 광고하지 않는다.
- 로컬 둘러보기는 샘플 표시를 고정한다. 샘플과 실 계정 캐시를 분리한다.
- 인수: 인터넷 없이 도움말·샘플 진입 가능, 실제 계정 작업은 연결 필요 안내, 첫 실행 여부 초기화 가능.

### W02 로그인

- 입력: 이메일, 비밀번호, 자동 로그인 선택, 비밀번호 보기. 비밀번호를 평문 설정 파일에 쓰지 않는다.
- 행동: 로그인 → 세션 검증 → 작업공간 선택 → 첫 PC 설정 또는 기존 회차 복귀.
- 에러: 계정 유무를 불필요하게 노출하지 않는 실패 문구, 네트워크 오류, 인증 만료, 이메일 확인 필요를 구분.
- 인수: Enter는 로그인 폼만 제출, 중복 요청 방지, 로그인 후 원래 요청한 권한 있는 화면으로 복귀.

### W03 회원 가입

- 입력: 기존 가입 폼 필드·약관 동의·이메일 확인. 비밀번호 강도는 서버 규칙과 맞춘다.
- 저장 후: 확인 이메일 안내와 재전송 대기시간. 가입 성공과 로그인 완료를 혼동하지 않는다.
- 인수: 기존 판매자 가입 흐름 보존, 확인 전 보호 화면 접근 차단, 오류 입력 보존.

### W04 비밀번호 재설정

- 이메일 입력 → 안내 → 메일의 안전한 재설정 경로 → 새 비밀번호. 외부 링크 복귀는 허용된 목적지만 수락.
- 상태: 요청 중, 접수, 링크 만료, 잘못된 링크, 변경 완료.
- 인수: 재설정 URL·토큰을 로그에 남기지 않음, 완료 후 로그인 동선 명확.

### W05 요금 안내

- 무료/유료 또는 기존 플랜의 기능·제한·가격·기간을 비교. 현재 가격은 서버 상품 카탈로그를 기준으로 한다.
- `플랜 선택`은 W21로 이어진다. 미연결 PG에서는 `결제 준비 중` 또는 테스트 모드를 표시한다.
- 인수: 기능 제한이 실제 권한과 일치, 세금·과금 기간·자동 갱신 설명이 구매 결정 전에 보임.

### W06 개인정보 안내

- 최신 적용 일자, 정책 버전, 수집 정보·목적·보관·삭제·문의 경로. 오프라인에서도 설치 버전의 정책 열람.
- 외부 링크는 안전한 시스템 브라우저로 열고 앱 내부의 권한 있는 웹뷰에 임의 페이지를 로드하지 않는다.
- 인수: 키보드 탐색, 텍스트 확대, 링크 식별, 정책 버전 기록. 법적 문서 내용은 실제 운영 방식에 맞춰 별도 검토.

## 4. 실시간 판매 화면

### W07 라이브 작업대 — 핵심 화면

레이아웃은 상품/오디오, 댓글, 판매 작성의 세 영역이다. 상단에는 작업공간·회차·녹음 상태, 하단에는 댓글·STT·클라우드·프린터의 상태가 남는다.

| 영역 | 필드·조작 | 검증 |
|---|---|---|
| 방송 회차 | 새 회차, 이어 하기, 종료, 시작 시각 | 종료 시 임시 입력·미확정 후보·미전송 확인 |
| 음성 입력 | 마이크/화면 오디오 선택, 입력 미터, 녹음 시작/중지 | 권한·입력 장치 없음·무음·중복 녹음 구분 |
| STT | 클라우드/로컬, 엔진·모델, 상태 | 없는 모델 다운로드 필요, 연결 오류·처리 지연 표시 |
| 자막 | 중간·확정 발화, 시간, 인식 명령 | 중간 발화를 확정 판매처럼 표시하지 않음 |
| 현재 상품 | 상품번호·이름·이미지·단가·스냅샷 | 상품 변경 시 기존 작성 내용 보존 여부 명시 |
| 댓글 | 사용자·본문·시각·근거, 검색, 새 댓글 개수 | 현재 작업공간/회차 범위, stable ID 선택 |
| 판매 작성 | 구매자, 단가, 수량, 합계, 메모, 근거 | 구매자·금액 규칙·수량 범위·중복 요청 |
| 결과 | 확정/보류, 최근 판매, 실행 취소 | 저장·동기화·인쇄 결과 분리 |

자동 판매와 수동 상품 판매는 진입 방법이 다르지만 주문 상태·금액 표현·근거 표시를 통일한다. 기존 두 저장 경로의 차이는 데이터 계층에서 명시하고, UI가 임의로 하나를 성공시켜 다른 것을 생략하지 않는다.

**기본 시나리오:** 회차 시작 → 댓글 연결 → 마이크 선택 → 상품 등록 → 댓글 구매자 선택 → 단가·수량 확인 → 확정 → 최근 기록 확인 → 필요 시 상세에서 정정.

**음성 시나리오:** 최종 발화 → 명령/구매자/가격 후보 추출 → 같은 회차 댓글 대조 → 근거 충족 시 정책에 따라 저장 또는 확인 대기 → 부족하면 보류 → 사용자가 근거와 금액 검토.

화면은 상품 등록·판매 확정·정정·캡처 명령을 모두 지원한다. 음성 파서의 별칭/가격 축약/후속 정정 규칙을 시각적 안내와 일치시킨다. 인식 결과를 클릭하면 원문과 적용 규칙을 볼 수 있다. 캡처는 사용자에게 선택된 화면/영역을 보여 준 뒤 진행한다.

**인수:** 새 댓글이 도착해도 선택 구매자가 바뀌지 않음, 확정 버튼 두 번 클릭/재연결에도 한 판매만 생성, 보류 이유 보존, 권한 철회 시 녹음 중단과 안내, 회차 변경 시 다른 회차 댓글이 근거로 사용되지 않음.

### W08 상품 판매

- 상단: 회차·현재 상품 등록/전환, 상품 목록 검색. 좌측 등록 폼, 중앙 댓글, 우측 판매 작성 구조를 W07과 공유.
- 등록 필드: 기존 상품 API 계약의 이름·단가·이미지·상품 스냅샷. 파일 선택·카메라/화면 캡처는 허용된 앱 API를 사용.
- 수정: 일반 상품 편집이 과거 판매 스냅샷을 조용히 바꾸지 않음. 기존 판매까지 바꾸는 명시적 작업은 `preview-product-change`/판매 변경 preview → 변경 전후 단가·수량·구매자·정산 영향 비교 → `commit` 순서로 제공한다. 영향받는 판매 수·금액·출력/청구 상태를 확인하며 stale preview는 다시 계산한다. 가격 변경 후 신규 판매에 적용될 기준도 표시한다.
- 판매: 댓글 구매자 식별자를 저장하고 고객 표시명과 분리. operationId로 중복 요청 방지, revision으로 동시 수정 감지.
- 인수: 웹과 Android의 상품 판매 계약과 같은 결과, 이미지 업로드 실패 복구, 미연결 프린터에서도 판매 결과 정상 표시.

### W09 음성 연습·훈련

- 원본의 훈련 UI와 진행 경험은 보존하되 실제 학습·모델 반영이 연결되지 않은 단계는 `연습/데모` 표시.
- 단계: 마이크 확인 → 제시 문장 읽기 → 인식 결과 비교 → 사용자 수정 → 연습 이력. 모델 학습을 했다고 표현하려면 데이터·잡·모델 버전 계약이 있어야 함.
- 입력: 명령·숫자·닉네임 연습 세트, 소음/장치 정보. 원음 저장 여부와 보관 정책 선택.
- 인수: 권한 취소·오디오 중지·재시도, 데모 결과가 실제 인식 성능 향상으로 광고되지 않음. 운영 완성은 별도 백엔드 인수 항목.

### W10 인식 규칙·캡처

- 탭: 인식 단어, 금액/명령 정책, 캡처 영역, 댓글 알림. 기존 규칙 추가·수정·삭제·활성화와 액션을 모두 제공.
- 규칙 표: 단어, 동작, 활성 상태, 수정 시간. 중복 단어·충돌 동작 검증과 문장 시험 입력 제공. 필수 규칙의 삭제/비활성화는 원래 보호 정책을 유지하고 이유를 표시한다.
- 캡처: 디스플레이/창 선택, 영역 드래그·크기 조절·프리셋·좌표·해상도·배율·미리보기·시험·공유 해제. 모니터 구성 변경 시 좌표를 그대로 맹신하지 않고 다시 확인.
- 댓글: 계정, 알림 단어, 알림 지속시간, 음성 명령. 실제 엔진 상태는 W20과 공유하는 단일 설정.
- 인수: 방송 중 규칙 변경의 적용 시점 명시, 삭제 후 복구 또는 확인, 잘못된 영역·권한 만료 표시.

### W11 댓글 기록

- 검색: 기간, 회차, 사용자, 본문, 구매 관련/전체. 표: 시각, 닉네임, 원문, 회차, 판매 연결 유무.
- 행 상세: 원문 ID·수집 시각·표시명·연결된 판매. 중복 댓글 또는 동명 닉네임을 별도 ID로 다룬다.
- 최신 댓글 이동·필터 초기화·CSV/TXT 내보내기는 권한 있는 자료만 대상으로 한다. 모든 페이지를 처리하고 완료 건수와 범위를 표시하며 기존 5,000건 조회 상한을 전체 내보내기로 오인하지 않는다.
- 삭제는 단건·선택한 행·현재 필터 전체를 구분한다. 페이지 밖 대상 건수·회차·복구 가능 여부를 확인하고 판매 근거로 참조되는 댓글의 보존/삭제 정책을 적용한다.
- 인수: 데이터 없음과 연결 실패 구별, 개인정보 마스킹, 현재 라이브 선택과 이력 조회 상태 분리.

## 5. 판매·후처리 화면

### W12 판매 내역

- 상단 KPI: 필터에 맞는 확정액, 확정 건수, 보류 건수, 전송 대기 건수. 집계 기준을 클릭/툴팁으로 확인.
- 필터: 회차·기간·상태·구매자·상품·입금/배송 상태, 검색. 정렬: 최신순 기본, 금액·구매자 지원.
- 표: 선택, 주문번호, 구매자, 상품, 수량, 단가/합계, 상태, 생성 시각, 동기화/출력. 구매자 그룹/개별 보기 전환을 유지하고 같은 필터에서 두 보기의 합계가 일치해야 한다. 우측 상세 버튼은 별도 접근 이름.
- 고객 패널: 구매정보 대조, 확인완료 처리, 고객 주소·금액 수정, 문의문자 작성/발신 상태, 수신 문자·MMS 첨부 보기. 구매횟수·누적액·첫 구매·미입금/취소 배지와 집계 범위를 표시한다. 전화번호·주소·문자 원문은 해당 권한에서만 볼 수 있다.
- 일괄 작업: 선택 개수·필터 범위·적용 가능 건수 표시. 확정·삭제·내보내기·출력 등 기존 행동을 권한대로 보존.
- 인수: 전체 선택이 현재 페이지인지 전체 검색 결과인지 분명, 보류는 매출 확정액에서 제외, 사용자 필터 유지.

### W13 판매 상세

- 서랍 너비 460~560px, 좁은 화면은 전체 페이지. 헤더 주문번호·상태, 본문 상품 스냅샷/구매자/가격/수량/메모.
- 근거 탭: 원문 발화, 댓글 일치, AI 근거·후보, 캡처. 이력 탭: 생성·정정·보류·확정·출력 이벤트.
- 행동: 수정, 구매자 후보 적용, AI 관련 요청/재시도, 캡처 확대, 인쇄/재출력, 삭제·취소. 서버 허용 상태에 따라 활성.
- 변경 저장 시 예상 revision과 operationId 사용. 충돌은 내 입력을 남기고 최신 자료와 비교.
- 인수: AI 후보 적용이 즉시 무조건 확정으로 바뀌지 않음, 출력 실패가 주문 저장을 취소하지 않음, 감사 기록 유지.

### W14 캡처 보기

- 검정 또는 중립 배경, 이미지 실제 비율, 확대/축소/100%/맞춤, 캡처 시각·판매번호. 여러 캡처의 이전/다음·현재 순번을 제공하며 화살표 키로 이동할 수 있다.
- `다운로드`는 사용자 권한·파일 정책 적용, 이미지 로딩/만료/없음 상태. Private Storage 서명 URL은 로그나 영구 문서에 노출 금지.
- 인수: Escape 닫기, 확대 후 키보드 조작, 창을 닫으면 원 판매 상세 초점 복귀.

### W15 보류·방송 후 검토

- 분할 화면: 왼쪽 사유별 보류 목록, 오른쪽 근거와 편집. 방송 후 전체 행 검토 모드도 제공.
- 보류 사유: 구매자 미일치, 가격 불명확, 중복 의심, 상품 확인, 연결/저장 확인 필요 등 실제 계약 값과 매핑.
- 여러 건을 빠르게 처리: 다음/이전, 수정 후 확정, 보류 유지, 제외. 원문·댓글·상품을 동시에 볼 수 있게 함.
- 일괄 확정은 적용 가능 건수를 검증하고 처리 결과를 항목별로 보여 준다. 부분 실패를 전체 성공으로 표시하지 않는다.
- 인수: 마지막 건 처리 후 빈 상태, 보류 총계 갱신, 다른 PC 동시 수정 충돌, 미확정 후보 유실 없음.

### W16 정산서 관리

- 좌측 고객별 목록, 우측 정산서 미리보기. 선택 기간/회차·상품별 수량·총액·배송비·입금/회신 상태.
- 생성·수정·취소·발송 준비·고객 회신·입금 매칭 등 기존 Commerce 동작을 보존하고 실제 서버/문자 기기 연결 여부 표시. 입금계좌·납기일·배송비·메시지 템플릿을 편집하며 취소가 연결 판매·입금·문자에 미칠 영향을 표시한다.
- 문자 발송 전 수신 대상, 마스킹 연락처, 메시지, 건수, 비용 발생 여부, 중복 발송 여부를 검토.
- 인수: UI상 발송 준비와 실제 기기 발송 완료 구분, 고객번호/연락처 중복 처리, 개인 정보 권한 확인.

### W17 배송 관리

- 필터: 주소 미확인/준비/발송/오류. 표: 고객, 주문, 주소 상태, 택배사, 운송장, 안내 메시지.
- 상세: 고객 회신 원문과 파싱 주소 비교, 수동 수정, 배송 묶음, 운송장 입력, 안내 문자.
- 포장완료·운송장 저장·수동 배송완료 등 기존 물류 상태 변경과 배송 안내 문자 전송을 분리한다. 물류 상태는 사용자의 명시적 처리 또는 검증된 연동 결과로 바뀌고, 문자 상태는 Android/서버 발신 결과로 바뀐다. 문자 전송 성공을 택배 배송 완료로 처리하지 않는다.
- 인수: 필수 주소 확인, 잘못된 운송장·중복 안내 방지, 권한 밖 고객 정보 차단, 원문과 수정 이력 분리.

### W18 정산

- 상단: 확정 판매액·확정 주문 건수·평균 주문액·보류 건수. 원본은 보류 제외 집계이므로 이 규칙을 보존.
- 보기: 일자별/회차별 그룹, 펼치면 해당 판매 목록. 기준 시간대·기간·제외 상태 명시.
- 내보내기: 전체 또는 그룹별 UTF-8 BOM CSV, 파일명에 기간/회차 포함. 통화 값은 숫자로 내보내고 헤더·형식 설명.
- 차트는 보조다. 같은 데이터의 표가 있어야 하며 차트 색만으로 비교하지 않는다.
- 인수: 화면 합계=내보낸 합계, 날짜 경계·보류·취소 정책 일치, Excel에서 한글 정상, 로컬 경로 선택 실패 복구.

## 6. 내장 엔진·기기 화면

### W19 기기 및 연결

- 탭: 이 PC, Android 기기, 출력 라우팅, 댓글, 음성. 등록 기기 이름·마지막 접속·권한·연결 상태.
- Android: 페어링 코드 생성, 만료, 연결 확인, 권한 변경, 연결 해제. 실제 문자 접근 권한을 Windows에서 대신 허용하는 것으로 표현하지 않는다.
- 출력: 기본 프린터/용지/사본, 자동 출력 토글, 워크스페이스 라우팅, 테스트 인쇄, 실패 대기열. `LABEL_50_30`, `RECEIPT_80`, `RECEIPT_58`, `A4` 네 용지 규격을 유지한다.
- 음성: 입력 장치, Python CPU/CUDA·Vulkan/클라우드 엔진, 모델 선택/다운로드/취소/시험, 실제 가속 상태. GPU 이름만으로 가속 성공이라고 표시하지 않는다.
- 인수: 장치 토큰 재노출 금지, 코드 만료/재사용 방지, 다른 작업공간 기기 보이지 않음, offline 상태 즉시 반영.

### W20 내장 댓글 연결

- 기존 도우미의 별도 설치 동선은 없어지고 앱 안의 댓글 탭으로 통합된다.
- 필드: 방송 계정, 연결 방식, 현재 room/session 정보, 자동 재연결, 수집 시작/중지. 고급 설정은 관리자·개발 정책 범위에서만 노출.
- 상태: 미설정, 준비, 연결 중, 수집 중, 재연결, 방송 종료, 인증/한도 오류, 엔진 오류.
- 진단: 최근 연결 시도 시각, 수집 개수, 마지막 댓글 시각, 재시도/진단 내보내기. 비밀과 고객 댓글 원문 제외 기본.
- 인수: 로그인·회차 준비 전 잘못된 자료 적재 방지, 내장 worker 종료·재시작 가능, 별도 helper 앱 설치 요구 없음.

### W33 첫 PC 연결 마법사

1. 로그인과 작업공간을 확인한다.
2. 마이크·화면 캡처 장치와 OS 권한을 설명하고 시험한다.
3. 댓글 계정을 입력하고 연결 상태를 확인한다.
4. STT 엔진을 선택한다. 로컬은 모델 크기·예상 다운로드·PC 요구사항을 안내한다.
5. 프린터 선택과 테스트, Android 연결은 선택 단계로 둔다.
6. 완료 화면에 준비/미설정 항목을 나란히 보여 주고 라이브로 이동한다.

중간 종료 후 이어 하기, 오프라인 설명, 단계별 오류 복구가 가능해야 한다. 아직 연결하지 않은 선택 기능 때문에 핵심 라이브 화면이 영구 차단되지 않게 한다.

### W34 연결·작업 센터

- 서비스별 상태 카드: 댓글 엔진, 오디오 캡처, 로컬/클라우드 STT, 클라우드 자료, 프린터, Android, 업데이트.
- 작업 목록: 다운로드·동기화·출력·진단. 진행률을 모르면 가짜 백분율 대신 진행 상태·경과 시간.
- `재시작` 영향: 녹음 일시 중단 여부, 댓글 누락 가능 구간, 기존 저장 자료 보존 여부를 표시.
- 인수: 서비스 하나 실패해도 다른 서비스의 정상 상태를 유지, 최근 성공 시간과 현재 오류를 함께 표시.

### W37 동기화·충돌 검토

- 대기/전송 중/실패/결과 확인 중/충돌/완료로 그룹. 각 작업에 회차·대상·발생 시각·재시도 결과.
- 충돌: 내 수정·서버 최신·원래 값 비교, 권한 있는 필드만 재적용. 삭제된 대상에 무단 재생성하지 않는다.
- 인수: 같은 operationId 재시도, 중복 주문 없음, 로그아웃 시 미전송 자료 처리 정책, 실패 원인과 다음 행동.

| 플랜 선택 | 현재 플랜·선택안·차이·과금 기간 | 가격·권한은 서버 카탈로그, 현재 구현의 플랜 UI 보존 |
| 결제 | 주문 요약·최종 금액·결제 제공자 이동 | 현재 PG 미연결/테스트는 명시. 카드 번호를 앱 자체 폼/로그에 저장하지 않음 |
| 구독 관리 | 갱신일·사용량·결제 이력·플랜 변경·해지 | UI만 있는 데이터는 데모로 표시. 권한은 검증된 서버 상태 반영 |

실제 판매 출시를 위해서는 결제 제공자·결과 검증·웹훅·중복 방지·환불·해지·구독 권한 계약을 추가 완성해야 한다. 결제창을 닫았다고 결제 실패로 단정하거나 프런트엔드 타이머로 유료 권한을 부여하지 않는다. 성공/실패/취소/결과 확인 중 화면을 별도로 만든다.

### W24 알림 설정

- 인앱/소리/Windows 알림과 이메일 알림 토글, 댓글 키워드, 판매 저장, 보류, 연결 끊김, 출력 실패 등의 설정을 기존 기능과 매핑. 이메일은 서버 이벤트·전달 결과를 연결하며 설정 저장만으로 시험 발송 성공을 표시하지 않는다.
- 방송 중 방해 최소화, 개인 정보가 잠금 화면에 나타나지 않는 기본값. 소리 미리듣기는 사용자 클릭으로만.
- 인수: OS 알림 권한/방해 금지 상태와 앱 설정 구분, 저장 결과·복구, 고대비·키보드 toggle, 명시한 시험 주소에서 이메일 수신 검증.

### W25 내 계정·백업

- 프로필·작업공간·계정 상태·환경·백업/복원/내보내기 관련 기존 동선을 보존. 음성 입력 선호, 로그아웃, 비밀번호 복구 진입도 제공한다.
- 회원 탈퇴는 삭제 대상·보관 대상 안내 → 재인증 → 서버 삭제 요청 → 접수/진행/완료 조회로 설계한다. 기존 alert+로그아웃을 실제 탈퇴로 표시하지 않는다. 실패 시 같은 요청의 상태를 조회하고 문의 경로를 제공한다.
- 백업은 포함 대상·제외 비밀·파일 위치·마지막 성공 시각·복원 영향 확인. 원본 웹에 UI만 있는 동작은 데모/미완성 구분.
- 인수: 기존 localStorage 자료 이전의 결과 보고, 다른 계정 백업 적용 차단, 로그아웃 후 민감 정보 정리.

### W26 권한 오류

- `이 작업을 수행할 권한이 없습니다` + 작업 이름 + 현재 작업공간 + 가능한 해결 경로.
- 버튼: 다시 확인, 작업공간 선택, 이전 화면. 서버 응답 전체·토큰·내부 스택 노출 금지.
- 인수: 무한 새로고침 금지, 취소 시 안정된 화면, 재로그인 후 권한 다시 검증.

### W35 앱 환경·업데이트

- 표시: 시스템/라이트/다크, 표준/컴팩트, 글자 크기, 움직임 줄이기, 언어/시간대.
- Windows: 시작 시 실행, 닫기 시 트레이, 녹음 중 종료 정책, 알림, 저장 위치.
- 업데이트: 현재 버전·채널·확인·다운로드·설치 예정·릴리스 노트. 방송 중 자동 재시작 금지.
- 인수: 설정 저장 실패 시 이전 값 복구, OS 창 버튼 정상, 업데이트 서명/검증 실패 안내, 롤백 경로.

### W36 명령 검색

- 검색 대상: 화면, 현재 권한의 행동, 최근 판매/상품(권한·범위 적용). 그룹별 검색 결과와 단축키.
- 위험 동작은 명령 검색에서 즉시 실행하지 않고 해당 검토 화면으로 이동.
- 인수: 방향키/Enter/Escape, 빈 결과, 오프라인 화면 검색, 포커스 복구.

### W38 도움말·진단

- 현재 화면 도움말, 설치/장치/댓글/음성/프린터 문제별 안내, 앱/엔진 버전, 비식별 진단 묶음.
- 지원 요청 전 포함 데이터 미리보기. 파일 경로·고객 정보·토큰을 무심코 전송하지 않음.
- 인수: 네트워크 없어도 기본 도움말 표시, 진단 저장 위치 선택·취소, 오류 코드로 관련 도움말 이동.

## 8. 관리자 화면

관리자는 같은 앱에서 별도 그룹을 사용한다. 일반 판매 업무 화면과 관리자 작업공간 범위를 혼동하지 않도록 헤더에 `관리자`와 조회 범위를 명시한다. 실제 서버 권한을 요구하며 로컬 role 변경으로 접근할 수 없어야 한다.

| 화면 | 구성·작업 | 상태·인수 |
|---|---|---|
| W27 대시보드 | 서비스/회원/판매 개요, 확인 필요 목록, 최근 사건, 전역 STT 제공자(Deepgram/Soniox) 선택·키 설정·사용 상태 | 집계 기간·범위·마지막 갱신 표시, mock 통계 구별. 원키 재조회 금지, 서버 저장/연결 시험/실패 상태 구분 |
| W28 판매 관리 | 작업공간/회원/회차/상태 필터, 판매 상세, 관리 작업 | 최소 권한·개인정보 마스킹, 변경 사유와 감사 기록 |
| W29 회원 관리 | 상태, 역할, STT 이용권, 검색·상세·상태 변경 | 권한 부여/회수 확인, 서버 정책 반영, 동일 회원 동시 수정 |
| W30 신고 관리 | 신고 목록·사유·상태·처리 메모 | 현재 UI 데모는 유지 표시, 실제 처리 API와 감사 기록 완성 필요 |
| W31 통계 | 기간별 추이·플랜·회원·판매 지표, 표/내보내기 | 샘플 통계를 운영 자료처럼 표시하지 않음, 지표 정의·권한 검수 |
| W32 AI 설정 | 기존 두 슬롯의 제공자·모델·역할·상태·진단 | 서버 비밀 노출 금지, 실제 연결 확인, 부분 실패, 변경 이력 |

AI 설정은 현재 설정 읽기 → 사용 가능한 모델 목록 → 임시 변경 → 진단 → 저장 순서다. `초안 저장`과 `즉시 적용`을 분리하고 draft/applied 버전·적용 시각·이전 버전 적용을 표시한다. 두 슬롯의 우선순위 교환, fallback 허용/조건, 자동 복귀, PC/클라우드 실행 위치, 비용 예산, health/model 목록·진단을 모두 제공한다. 실패한 변경이 기존 적용 버전을 덮어쓰지 않게 한다. 클라이언트에 서비스 관리자 키를 넣는 방식으로 편의상 해결하지 않는다. 진단 응답은 민감한 프롬프트·고객 자료·인증 헤더를 노출하지 않는다.

## 9. 흐름별 수용 검증

| 흐름 | 검수 절차 | 완료 조건 |
|---|---|---|
| 처음 설치 | 로그인→PC 설정→댓글·STT 준비→라이브 | 별도 도우미 없이 화면 내 상태 확인 |
| 음성 판매 | 발화→후보→댓글 일치→판매 저장 | 원문·근거·주문 연결, 중복 없음 |
| 수동 상품 판매 | 상품 등록→댓글 선택→수량 변경→확정 | 상품 스냅샷·구매자·합계 정확 |
| 보류 복구 | 미일치 보류→상세 수정→확정 | 보류 제거·집계 반영·감사 기록 |
| 출력 | 확정→인쇄 실패→재출력 | 주문 중복 없이 출력 상태만 변경 |
| 오프라인 | 연결 중단→허용 작업→복구→동기화 | 전송 대기와 확정 구분, 충돌 처리 |
| 정산 | 기간/회차 변경→그룹 펼침→CSV | 화면과 CSV 합계 동일 |
| 문자/배송 | 정산서 준비→기기 발송→회신→배송 안내 | 실제 기기 결과가 완료 상태 결정 |
| 구독 | 플랜 선택→테스트/실제 PG→결과 검증 | 환경 구별, 검증 전 유료 권한 없음 |
| 관리자 | 판매자 계정/관리자 계정 각각 시도 | UI와 서버 모두 권한 차단 일치 |

각 화면의 원본 세부 필드는 [기존 웹 설계](../docs/replication/02_WEB_DESIGN.md)와 해당 [소스 디렉터리](../src/pages)를 함께 읽어 옮긴다. 이 화면 설계가 데이터 필드를 임의로 삭제하는 근거가 되어서는 안 된다.

## 10. 첨부 시안의 범위와 검수 방법

`prototype/index.html`을 브라우저에서 열면 라이브·판매 내역·정산을 볼 수 있다. 댓글 선택, 단가/수량 수정, 가짜 확정/보류, 판매 상세, 테마·밀도, 연결 상태, 설정, 샘플 CSV 내보내기를 조작할 수 있다. 재로딩 시 가짜 판매 상태는 초기화된다. 실 계정 로그인, STT, 방송, 파일 캡처, 인쇄, 결제는 연결하지 않았다.

1. 댓글을 선택하고 수량을 2로 바꿔 합계가 변하는지 확인한다.
2. 판매 확정 후 판매 목록과 정산에서 같은 가짜 합계가 보이는지 확인한다.
3. 보류 저장 후 매출 합계에서 제외되고 보류 필터에서 조회되는지 확인한다.
4. 상세를 열고 수정/확정/보류가 표시 데이터에 반영되는지 확인한다.
5. 설정에서 테마·밀도를 바꾸고 연결을 끊어도 샘플 시안이라는 표시가 유지되는지 확인한다.
6. 1280/1440/1920 너비 및 확대·키보드 조작을 검사한다. 시안과 실제 Windows 배율 검증은 별도로 기록한다.

시안의 예시는 고객·운영 자료가 아니다. UI 품질 검토를 위한 시작점이며 전 화면의 실제 구현 완료를 의미하지 않는다.
