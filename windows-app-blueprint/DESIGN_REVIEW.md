## 2. 색 토큰 계산

04장의 HEX 값으로 sRGB 상대 휘도와 대비를 계산했다. 카드 배경 위의 기본/보조/약한 텍스트 및 성공/경고/오류색 6개 조합을 각 테마에서 비교했다.

| 대상 | 계산 결과 |
|---|---|
| 라이트 텍스트·상태 6개 / 흰 카드 | 4.76:1~15.20:1 |
| 다크 텍스트·상태 6개 / `#172130` 카드 | 6.98:1~14.67:1 |
| 라이트 주 버튼 | 6.10:1 |
| 다크 주 버튼 | 7.62:1 |

이는 지정한 색 쌍의 수학적 확인이다. 실제 반투명 배경·hover·disabled·선택 상태·사진 위 글자·OS 고대비·Narrator·모든 화면의 접근성 인증을 완료했다는 뜻은 아니다. 구현 후 G08에서 실제 조합을 검사한다.

## 3. 시안 조작 검토

`127.0.0.1`에서 이 설계 폴더만 제공하는 임시 서버와 브라우저를 사용했다. 외부 로그인·방송·마이크·결제·실제 인쇄·SMS는 실행하지 않았다.

| 검수 | 확인한 결과 |
|---|---|
| 라이브 초기 상태 | 가짜 확정액 231,000원, 확정 6건, 보류 2건 |
| 구매자 선택·수량 | 지니 선택, 29,000원 × 3 = 87,000원 |
| 확정→정산 | 확정액 318,000원, 확정 7건으로 일치 |
| 보류 | 다온 29,000원 보류 후 확정액 318,000원 유지, 보류 3건·필터 3행 |
| 상세 수정 | 위 보류를 수량 2·확정으로 바꾸자 확정액 376,000원, 확정 8건, 보류 2건 |
| 설정 | 라이트/다크·표준/컴팩트 변경 동작 |
| 연결 상태 | 샘플 연결 끊김에서 상태줄·댓글 수집 상태·연결 센터가 함께 변경 |
| 다크 보완 | body의 색 토큰 해석 문제를 수정하고 재확인. 배경 `rgb(14,20,32)`, 글자 `rgb(240,244,250)` |
| 가격 정책 | 0원은 저장 가능. 실제로 입력을 지운 빈값은 invalid이고 저장 후 확정 건수 증가 없음 |
| 반응형 | 390/768/1280/1440/1920 CSS viewport에서 라이브 레이아웃 확인. 검사한 문서 폭에서 페이지 전체 가로 overflow 없음 |
| JavaScript | `node --check prototype/app.js` 통과, 확인한 브라우저 error 로그 없음 |
| 자산 | HTML/CSS/JS·인라인 SVG 기반, 외부 CDN·실제 API 호출 없음 |

검수 후 샘플 주문·테마는 새로고침으로 기본 상태로 돌렸다. 브라우저 viewport 시험은 실제 Windows 125/150/200% DPI·Narrator·프린터·모든 페이지 인수를 대신하지 않는다. CSV는 생성 코드의 BOM·필터·인용부호 처리와 샘플 전용임을 검토했으며 이번 브라우저 조작에서는 다운로드하지 않았다. 일부 안내용 버튼은 실제 기능 대신 명시적인 시안 설명을 연다.

## 4. 설계 후 연구 결과

추가안 10개를 공식 문서와 현재 코드에 연결해 비교했다. 우선 실험 대상은 AudioWorklet, 가상 목록·분리 구독, 변경 알림과 증분 동기화, 짧은 DB batch, STT 프로필, 단계별 초기화다. 특정 앱 오디오·인쇄 창 재사용·다른 프레임워크는 기능 동등성과 유지비까지 비교한 뒤 결정하도록 했다.

SQLite WAL 패치 이력과 철회 버전은 추가 출시 검증 항목으로 기록했다. 실제 새 앱 성능을 측정하거나 효율 향상 수치를 검증한 것은 아니며, 부록의 모든 성능 기대는 가설 또는 계산 예시로 구분했다.

## 5. 구현 전에 확정하고 검증할 사항

- 외부 브라우저 탭 단독 오디오의 동등성: 시스템 loopback 지원과 같은 의미가 아니다. 지원 조합을 실측한다.
- PG·이메일·TikTok·STT·AI 공급자 연결, 모델·바이너리·폰트의 배포 조건, 코드 서명·업데이트 공급 경로.
- 운영 DB와 소스 migration의 차이, 서버 RLS·transaction·job consumer 보완, Android 실제 repository·SMS/MMS 동작.
- 성능 목표와 STT 판매 정확도, 8시간 방송 부하, 프린터/오디오/GPU/배율 지원표.
- 새 앱의 67개 기능별 증거와 10개 출시 gate. 이번 문서는 해당 기능을 구현·검증할 설계다.

이번 작업은 기존 앱 코드나 운영 DB를 변경하지 않는다. 기존 테스트가 실제 사용자 STT 설정에 쓰는 문제가 알려져 있으므로 문서 작업을 위해 원본 앱 테스트를 반복 실행하지 않았다. 신규 구현의 테스트 격리 방법은 06·07에 명시했다.
